## 0. 一行で言うと

**3〜6人が円になり、カードを箱に投入するたびに楽器の音が加わって、3分間で1曲を共同生成する、勝敗のないカードゲーム。**

---

## 1. 企画の骨子

| 項目 | 内容 |
|---|---|
| タイトル | ミクスチャー・サークル（仮） |
| ジャンル | 音楽生成型・協調体験カードゲーム |
| 人数 | 3〜6人 |
| 所要時間 | 1ゲーム 3分（1分／2分／3分／5分から選択可） |
| 勝敗 | **なし**（体験共有型） |
| テーマ | 音楽のミクスチャーによる「融和」。競争ではなく共同創造 |
| 特徴 | 言語に依存しない／音楽経験不要／毎回違う曲になる |

**円形に座ることの意味づけ：** 対立のない構造の象徴。手番の順序も存在しない。

---

## 2. 現行ルール（実装済みのものを含む確定仕様）

### 2-1. 進行

1. 3〜6人が円形に座る
2. カードをランダムに配布（各プレイヤー数枚）
3. 開始前にテンポ（BPM）と制限時間を選ぶ
4. 基礎ビート（4拍子のドラムループ）が鳴り始める
5. 各プレイヤーは**好きなタイミングで**カードを箱に投入（手番なし・順序なし）
6. 箱がカードを検知 → **次の拍頭から**その音が同期して加わる
7. 制限時間で終了 → 完成した曲をみんなで聴き、感想を共有する

**「投入した瞬間ではなく次の拍頭から鳴る」** ことが技術的にも体験的にも核。ズレた音が入らないので、誰が入れても曲が破綻しない。

### 2-2. 実装済みの細則（Phase 0 / STUDIO 版アプリで実際に動いている挙動）

| ルール | 値・挙動 | 意図 |
|---|---|---|
| 同時発音パート数 | **最大6**。7つ目を入れると**最も古いパートがフェードアウトして抜ける** | 音が飽和して団子にならないようにする |
| 同じカードの重複投入 | 既に鳴っているカードは**無視**（「その音はもう鳴っています」と表示） | 二重再生の防止 |
| 二重読みガード | 同一カードの再入力を **500ms** 無視 | リーダーの連続読み対策 |
| 音量の自動調整 | パート数が増えるほど各パートの音量を下げ、合計音量を一定に保つ | 重ねても割れない |
| BPM | **70〜150** から選択（既定 96） | 速い＝混沌、遅い＝融和 |
| 終了処理 | 制限時間で自動終了、録音を再生・保存できる | 「聴き返して共有する」ため |

### 2-3. 「濁り」を制御する4つの仕掛け

企画書は「濁った混沌も価値」とするが、**何をしても不快**では体験にならない。以下で「破綻しない濁り」を作っている。

1. **キーの固定** — 全音素材を Cマイナー・ペンタトニック に統一。何を重ねても音楽的に成立する
2. **周波数の住み分け** — ベース＝低域、ギター/ピアノ＝中域、シンセ/ブラス＝高域。同じ帯域で殴り合わせない
3. **同時発音数の上限** — 上記の6パート制限
4. **ジャンル＝リズムの性格** — ジャズ＝スウィング/裏拍、ロック＝8分/強拍、クラシック＝伸びる音、エレクトロ＝16分/機械的

## 3. カード仕様

### 3-1. 構造：楽器 × ジャンル性格の二層

カード1枚 ＝ 「楽器」と「ジャンル性格」の組み合わせ1つ。

**プロトタイプは 6楽器 × 4ジャンル ＝ 24枚**（企画書の 10楽器 × 5ジャンル ＝ 50枚 は拡張枠）。

| | ジャズ（深い青） | ロック（赤黒） | クラシック（白金） | エレクトロ（ネオン） |
|---|:---:|:---:|:---:|:---:|
| ピアノ | ● | ● | ● | ● |
| ギター | ● | ● | ● | ● |
| ベース | ● | ● | ● | ● |
| ドラム | ● | ● | ● | ● |
| ブラス | ● | ● | ● | ● |
| シンセ | ● | ● | ● | ● |

> 企画書初版では「ストリングス」だったが、実装時に**ブラス**へ差し替えた（重ねたときの抜けの良さのため）。
> 企画書にある**民族音楽ジャンル**と、サックス／バイオリン／フルート／パーカッションは**拡張枠として未実装**。

### 3-2. ジャンルの性格づけ（企画書の定義）

| ジャンル | 色 | 模様・線 | 音の性格 |
|---|---|---|---|
| ジャズ | 深い青 | 夜景、柔らかい線 | スウィング感、裏拍 |
| ロック | 赤黒 | 稲妻、荒々しい線 | 力強いリフ、8分・強拍 |
| クラシック | 白金 | ホール装飾 | 優雅な響き、伸びる音 |
| 民族音楽（未実装） | 土色 | 自然模様 | 太鼓や笛 |
| エレクトロ | ネオン | 幾何学 | 未来的なシンセ、16分・機械的 |

### 3-3. 物理仕様

| 項目 | 仕様 |
|---|---|
| サイズ | 63 × 88mm（TCG標準） |
| 構造 | 印刷面（紙）＋芯（厚紙）＋NFCシール＋裏面（紙） |
| 厚さ | 1.5mm以下（投入口を通ること） |
| シール位置 | **全カードで同じ位置（中央）**。ばらつくと読み取り率が落ちる |
| 表面保護 | ラミネート等（**方法は未決**） |

### 3-4. デザイン原則

- **楽器が主役**：中央に大きく楽器の図像
- **背景がジャンルの性格**：色・模様・線の質で表現
- **1m離れても、円の対面から何のカードか分かること**

## 4. 物理デバイス（箱）の現状

- **方式：USB HID タイプの RFID リーダー ＋ NFCシール**（キーボードとして認識され、UIDを打ち込んでEnterを押す）
- 構造：投入口 → 傾斜スロープ（滑走） → リーダーで検知 → カード受けトレイに落ちる
- リーダーとシールは**発注済み・到着待ち**。到着日にUID登録とスロープの位置合わせを行う予定
- リーダーがなくても**キーボード入力で完全に同じ経路をテストできる**設計

### 4-1. すでに認識している「箱」側の弱点

現行方式では、検知は「通過した瞬間」の一点のみ。カードはトレイに落ちて役目を終える。

- 山にはなるが、**山の形・置き場所に意味がない**（ただの排出先）
- 「誰が・どの音を・いつ足したか」を後から目で追いにくい
- 企画の本質である「**積み重ねる**」手応えが弱い

検討した代替案は2つある（どちらも未採用）：

- **光学バーコード方式**：カードの縁に印刷パターン、反射型光センサで読む。シール代が不要。読み取り後にカードを自由に配置できる
- **陣地（ポケット）方式**：枠ごとにセンサを仕込み、**カードの配置そのものが「今鳴っている曲の構成」を表す**。体験としては最も忠実だが配線量が多い

> 補足：NFCタグを**直接積み重ねて一括読み取り**するのは、13.56MHz帯タグの磁気的な相互干渉により信頼性が低く、技術的に採らない判断をしている。

## 5. 現在動いているもの（プロトタイプ）

キーボードをカードの代わりにする**ブラウザアプリが2種類**完成し、実際に音が出る状態。

| | Phase 0 版 | STUDIO 版 |
|---|---|---|
| 音 | すべて合成音（Tone.js） | ピアノ/ギター/ベース/ブラス/ドラムは**実録音サンプル**、シンセのみ合成音 |
| 位置づけ | 「面白いか」を確かめるための最小版 | 音のリアリティを上げた版 |

キー配置は「行＝ジャンル、列＝楽器」の 4×6 グリッド（`1`〜`6` がジャズ、`Q`〜`Y` がロック、`A`〜`H` がクラシック、`Z`〜`N` がエレクトロ）。

**未確認：** 実際に人を集めて遊んだときの手応え（プレイテスト未実施）。音量バランスも耳での調整が済んでいない。

### 6-2. すでに下している設計判断（覆すなら理由が要る）

- **勝敗を作らない**（体験共有型であること自体がコンセプト）
- **手番を作らない**（円形＝順序のない構造という象徴と結びついている）
- **キーを1つに固定する**（何を重ねても破綻しないための土台）
- **同時6パート上限**（音の飽和を防ぐ）
- **画面はプレイヤーに見せない**（進行役だけが見る。体験の主役は物理カードと音）

## 8. 制約条件（提案の前提として）

- 制作者は個人。予算は部品代で数千円〜1万円規模
- 実装はブラウザアプリ（HTML/JS + Tone.js）、箱は段ボール工作＋USB接続の市販リーダー
- 音素材は**公開予定があるためライセンスに厳格**（CC0または自作合成音に限定）
- 到着待ちの部品があり、**約1週間後に物理版を一気に完成させる**スケジュール
- 現状は**プレイテスト未実施**。したがって「面白いかどうか」は誰も確かめていない
