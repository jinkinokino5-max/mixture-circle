# ミクスチャー・サークル 実装計画（プロトタイプ版）

作成日：2026-08-04
対象：`reference/アイデア.txt`（コードブック仕様書）の実装
制約：**予算 20,000円以内 / 電子工作の知識ゼロ / 電子部品の手持ちなし / 紙・はさみ・のり等の工作材料はあり**

---

## 0. 結論（先に3行）

1. 企画書の「Raspberry Pi + RFIDリーダー」案は**採らない**。予算の大半を本体まわりに取られ、初心者が最初に触る対象としては失敗確率が高い。
2. 代わりに **「手持ちのPC + USB接続RFIDリーダー（HIDタイプ） + 自作の段ボール箱 + ブラウザ（Web Audio API）」** で作る。
3. 電子工作は Phase 2 の「LED演出」から入る。**作品の中核が動いてから**、壊れても困らない場所で入門する。

---

## 1. システム構成

```
 ┌─ カード（紙で自作 + 裏面にNFCシール）
 │
 ▼ 投入口に入れる
┌──────────────────────┐
│  箱（段ボールで自作）           │
│   ├ 傾斜スロープ（カードを"落とす"のではなく"滑らせる"）│
│   ├ USB RFIDリーダー（スロープの真下に固定）      │
│   └ カード受け（読み取り後にたまる）           │
└───────────┬──────────┘
            │ USBケーブル（キーボードとして認識される）
            ▼
┌──────────────────────┐
│  PC（手持ち） / ブラウザで動くアプリ          │
│   ├ カードUID → 楽器×ジャンル に変換          │
│   ├ Tone.js で基礎ビート＋各パートを生成       │
│   └ 拍頭に同期して発音・ミックス・タイマー管理    │
└───────────┬──────────┘
            ▼
        スピーカー（手持ち or Phase2で購入）
```

### なぜ「HIDタイプのUSB RFIDリーダー」なのか

このリーダーは、**OSからは「キーボード」に見える**。カードをかざすと、カードのUID（例：`0004512345`）を文字として打ち込み、最後にEnterを押してくれる。

つまり：

- ドライバのインストール不要（挿すだけ）
- はんだ付け・配線・ブレッドボード一切不要
- プログラム側は「キーボード入力を受け取る」だけ（`keydown` イベント）
- Windows / Mac / Linux / Raspberry Pi、どこに挿しても同じように動く

**電子工作の知識ゼロでも、届いた日にメモ帳を開いてカードをかざせば動作確認が完了する。** これが最大の理由。

### 構成案の比較（判断の根拠）

| | A案：Raspberry Pi + RC522 | B案：PC + USB HIDリーダー（**採用**） |
|---|---|---|
| 初期費用 | Pi本体・電源・SDカード・スピーカーで予算の大半 | リーダー1個で済む |
| 必要な電子工作 | ジャンパ配線・SPI設定・はんだ付けの可能性 | **ゼロ** |
| 最初に音が出るまで | OS設定・音声出力設定でハマりやすい | ブラウザを開いた瞬間 |
| 拍同期の精度 | Pythonで自前実装が必要 | Tone.js の Transport が担当（実績あり） |
| 開発のしやすさ | SSH経由・画面なし・デバッグが遠い | 手元のエディタとブラウザ、`F12` で完結 |
| 自立性（PCなしで動く） | ◎ | ✕（PCが必要） |
| 展示・持ち運び | 電源だけでOK | ノートPCを一緒に持ち込む |

B案の唯一の弱点は「PCが必要」だが、**プロトタイプ段階では弱点にならない**。自立化は作品が完成し、価値が確認できてからの課題（Phase 4以降・予算外）。

## 3. フェーズ計画

### Phase 0：紙とキーボードで「面白い」を確かめる（第1週 / 費用 0円）

**ゴール：RFIDリーダーが届く前に、ゲームとして成立するか判断する。**

やること：

1. 紙でカードを24枚つくる（6楽器 × 4ジャンル）。手描きでよい
2. ブラウザで動く音アプリを作る。カードの代わりに **キーボードの `1`〜`9`, `q`〜`o` キー** で音を追加する
3. 基礎ビート（4拍子ドラムループ）を鳴らす
4. 友人3〜6人に、キーボードを回して遊んでもらう

**完了条件（DoD）：**

- [ ] 基礎ビートが途切れずに鳴り続ける
- [ ] キーを押すと、**次の拍頭から**音が追加される（押した瞬間ではない）
- [ ] 3種類以上の音を重ねても破綻しない
- [ ] 誰かが1回でも「もう1回やろう」と言った

**なぜこれを先にやるのか：** ハードウェアは「入力方法」でしかない。面白さの99%は音と進行の設計にある。ここで面白くなければ、RFIDにしても面白くならない。逆にここで面白ければ、あとは体験の質を上げる作業になる。

---

### Phase 1：RFID化して「箱」にする（第2〜3週 / 約4,000〜8,500円）

**ゴール：企画書のコア体験がそのまま動く状態。**

やること：

1. リーダーが届いたら、まずメモ帳を開いてシールをかざす → UIDが打ち込まれることを確認
2. UIDを全24枚ぶん記録して `cards.json` を作る（UID → 楽器 + ジャンル）
3. Phase 0 のアプリのキーボード入力部分を、UID入力に差し替える
4. 段ボールで箱をつくる（→ 4章の設計）
5. カードを清書して仕上げる（→ 5章の仕様）

**完了条件（DoD）：**

- [ ] カードを投入口に入れると、95%以上の確率で1回で読み取れる
- [ ] 同じカードを2回入れても、音が二重に鳴らない（連続読みのガード）
- [ ] 制限時間（例：3分）で自動的に終わり、余韻を残して止まる
- [ ] 電源とPCを繋いで5分以内にセットアップできる

---

### Phase 2：演出と音質（第4〜6週 / 約4,700〜11,100円）

**ゴール：「体験」として人に見せられる完成度。ここで初めて電子工作に入門する。**

やること：

1. **音質** — スピーカーを箱に組み込む。箱の共鳴を利用する／殺す設計
2. **電子工作の入門** — ESP32 + ブレッドボードで、LEDを光らせるところから始める
   - Lチカ → PWMで明るさ調整 → NeoPixelテープを1色に → 拍に合わせて光らせる
3. **連携** — PCのアプリから、拍のタイミングと投入イベントをESP32に送り、円形LEDを光らせる
   - 通信は WebSerial（USB経由）または WebSocket（Wi-Fi経由）
4. カードデザインの本清書（ジャンル＝色と模様、楽器＝主役の図像）

**完了条件（DoD）：**

- [ ] 基礎ビートに合わせて光が脈打つ
- [ ] カード投入時に、その色（ジャンル色）で光が走る
- [ ] 部屋を暗くして遊ぶと、明らかに体験の質が上がっている

**ここで電子工作をやる理由：** LEDは、失敗しても「光らない」だけで作品は動き続ける。中核機能をLEDに依存させないことで、安心して試行錯誤できる。これは初心者が新技術を導入するときの定石。

## 4. 箱の設計（段ボール）

### 読み取りを安定させるための要点

企画書の「RFID読み取りの速度と安定性が重要」に対する具体策。

```
        カード投入口（幅70mm × 高さ5mm）
              │
              ▼
        ╱╱╱╱╱╱╱╱      ← 傾斜スロープ（約30〜40度）
       ╱                  カードを"落とす"のではなく"滑らせる"
      ╱   [リーダー]   ← スロープの裏側に密着させて固定
     ╱      ▲            （読み取り面が上向き、カード面と2〜4cm以内）
    ╱_______│_______
      カード受けトレイ
```

| 設計項目 | 指定 | 理由 |
|---|---|---|
| 投入方式 | 落下ではなく**傾斜スロープで滑走** | 落下は通過が速すぎて読み逃す。滑走なら0.3〜0.5秒かけてリーダー上を通る |
| リーダーの位置 | スロープ裏に密着、カード面から2〜4cm | 一般的なHIDリーダーの読み取り距離は最大8cm程度だが、余裕を持たせる |
| リーダー周辺の材質 | **金属を使わない**（段ボール・木・プラのみ） | 13.56MHzの磁界が金属で乱れ、読み取り不能になる |
| スロープの幅 | カード幅 + 3mm | 斜めに入って詰まるのを防ぐ |
| 投入口の高さ | 5mm程度 | 2枚同時投入を物理的に防ぐ |
| スピーカー位置 | 箱の側面・下向き | 円に座る全員に均等に届く |
| ケーブル出口 | 背面下部に切り欠き | 見た目と、引っ張られたときの断線防止 |

**作り方の順序：** ①段ボールでスロープだけ作って読み取りテスト → ②成功率95%以上を確認 → ③その寸法を採用して箱全体を作る。**箱を先に作らないこと。**

## 5. カード仕様

### 組み合わせ

プロトタイプは **6楽器 × 4ジャンル = 24枚** に絞る。

| | ジャズ（深い青） | ロック（赤黒） | クラシック（白金） | エレクトロ（ネオン） |
|---|---|---|---|---|
| ピアノ | ● | ● | ● | ● |
| ギター | ● | ● | ● | ● |
| ベース | ● | ● | ● | ● |
| ドラム | ● | ● | ● | ● |
| ストリングス | ● | ● | ● | ● |
| シンセ | ● | ● | ● | ● |

企画書の10楽器 × 5ジャンル = 50通りは、**音素材を50個作る作業量**を意味する。まず24個で体験を確かめ、良ければ拡張する。民族音楽・管楽器は拡張枠。

### 物理仕様

| 項目 | 仕様 |
|---|---|
| サイズ | 63 × 88mm（トランプ／TCG標準サイズ） |
| 構造 | 印刷面（紙） + 芯（厚紙） + NFCシール + 裏面（紙） |
| 厚さ | 1.5mm以下（投入口を通ること） |
| シール位置 | **全カードで同じ位置**（中央）に貼る。位置がばらつくと読み取り率が落ちる |
| 角 | 角丸に切る（耐久性と手触り） |
| 表面保護 | 透明テープ or ラミネート（何度も投入するため） |

### デザイン原則（企画書より）

- **楽器が主役**：中央に大きく楽器の図像
- **背景がジャンルの性格**：色・模様・線の質でジャンルを表現
- **1m離れても、円の対面から何のカードか分かる**こと

## 6. 音楽システムの設計方針

### 重要な設計判断：「音のサンプル」ではなく「合成音」から始める

企画書には「短いループ素材」「テンポに応じて自動タイムストレッチ」とある。しかしプロトタイプでは、**Tone.js による音の合成（シンセサイズ）** を第一候補とする。

| | 録音サンプル方式 | 合成方式（**採用**） |
|---|---|---|
| BPM変更 | タイムストレッチが必要（音質が劣化する、実装が難しい） | **不要**（テンポを変えるだけで自動追従） |
| 音素材の用意 | 24個の音源を録音 or 探す | コードでパターンを書く |
| ライセンス | 素材ごとに要確認。トラブルの温床 | **完全に自作＝問題ゼロ** |
| 費用 | 有料素材だと数千〜数万円 | **0円** |
| 音のリアルさ | ◎ | △（電子音寄りになる） |

**方針：** まず全パートを合成音で作る（Phase 0〜1）。体験が確立したら、リアルさが欲しいパートだけをサンプルに差し替える（Phase 2以降）。

### 「濁り」をコントロールする仕組み

企画書は「濁った混沌も価値」としているが、**何をしても不快になる**のでは体験にならない。以下の制約で「破綻しない濁り」を作る。

| 手法 | 内容 |
|---|---|
| **キーの固定** | 全音素材を1つのキー（例：Cマイナー・ペンタトニック）に統一する。何を重ねても音楽的に成立する |
| **周波数の住み分け** | ベースは低域、ピアノ/ギターは中域、シンセ/ストリングスは高域。同じ帯域で殴り合わせない |
| **同時発音数の上限** | 同時に鳴るパートは最大6つ。7つ目が入ったら最も古いものをフェードアウト |
| **音量の自動調整** | パートが増えるほど、1つあたりの音量を下げる（合計音量を一定に保つ） |
| **ジャンル＝リズムの性格** | ジャズ＝スウィング・裏拍、ロック＝8分・強拍、クラシック＝伸びる音、エレクトロ＝16分・機械的 |

### 同期の実装方針

```
Tone.Transport（全体の時計）
  ├ 基礎ビート：4拍子のドラムループを常時ループ再生
  └ カード投入 → 「次の小節頭」に予約 → その時刻から該当パートを開始
```

投入した瞬間ではなく **次の拍頭／小節頭にキューイングする** ことが、企画書の「⑤投入 → 次の拍頭から音が追加」の実装。これがこの作品の技術的な心臓部。

## 7. リスクと対策

| リスク | 起きること | 対策 |
|---|---|---|
| **読み逃し** | カードを入れたのに音が出ない | 傾斜スロープで滑走させる／読み取り成功時に**音とLEDで即フィードバック**（無音だと投入者が不安になる） |
| **二重読み** | 1枚で2回鳴る | 同一UIDの連続入力を500ms間無視するガード処理 |
| **リーダーが期待した動作をしない** | HID出力でない・フォーマットが違う | 発注前に商品説明で「キーボード入力として出力」を確認。届いたら**まずメモ帳でテスト** |
| **音が濁って不快** | 遊んでいて楽しくない | 6章の制約を最初から入れる。キー固定は必須 |
| **当日のPCトラブル** | 展示・発表で動かない | 使うPCで事前に通しリハーサル／ブラウザのオーディオ自動再生ブロックに注意（開始ボタンを必ず設ける） |
| **カードの物理的劣化** | 何十回も投入して折れる | ラミネート／予備セットを作る |
| **予算超過** | Phase 2が買えない | Phase 1だけ先に発注し、残額を確認してから決める |
