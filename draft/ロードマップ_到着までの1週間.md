## 2. 完成の定義（DoD）

到着日の終わりに、以下がすべて ✓ になっている状態を「完成」とする。

- [ ] カードを投入口に入れると、**95%以上の確率で1回で読み取れる**
- [ ] 同じカードを2回入れても音が二重にならない（連続読みガード）
- [ ] 読み取り成功が**音のフィードバック**で即座にわかる（無音だと投入者が不安になる）
- [ ] 制限時間（3分）で自動的に終わり、余韻を残して止まる
- [ ] PCを繋いで**5分以内**にセットアップできる
- [ ] 全24枚（または確定した枚数）のカードが物理的に完成し、UID登録済み

## 3. 全体の構造：3本のトラックを並行で進める

作業は独立した3本に分かれる。互いに待たずに進められる。

```
【A】音トラック   素材収集 → 音楽エンジン設計 → 本番アプリに実装
                  ↑ 所要時間が読めない。最優先で着手、いつ止めてもよい形にする
【B】アプリトラック RFID入力モジュール → 本番アプリの骨格 → 進行役画面
                  ↑ リーダーなしでキーボードで代用テストできる
【C】物理トラック  スロープ試作 → カード清書 → 箱本体
                  ↑ リーダーの実寸が要るので「寸法可変」で作る
                          ↓
                    到着日：合流（UID登録＋位置合わせ）
```

**この構造にする理由：** 音の作り直しは「どこまでやれば満足か」が事前に決まらない作業。ここに引きずられて Phase 1 が未完成になるのを防ぐため、A が途中で止まっても B と C だけで DoD を満たせるようにする。具体的には、**本番アプリの初期状態を「studio-app の音をそのまま持ってきたもの」にしておき**、ループ素材が揃った分だけ差し替えていく。

## 4. 技術設計の要点

### 4-1. ループ素材でBPM可変を実現する方法

ループ素材は録音時のテンポが固定されているため、そのまま再生速度を変えると**音の高さも一緒に変わる**（キーが狂う）。これを解決する必要がある。

**採用する方法：`Tone.GrainPlayer`**

Tone.js には `GrainPlayer` というノードがあり、**再生速度（`playbackRate`）と音の高さ（`detune`）を独立して指定できる**（グラニュラー方式のタイムストレッチ）。

```
素材の録音BPM = 100 のループを、BPM 90 で鳴らしたい場合
  playbackRate = 90 / 100 = 0.9   ← 速度だけ遅くする
  detune = 0                      ← 音の高さはそのまま
```

- **品質の目安：** ±10〜15% 程度の変化なら実用に耐える。それを超えると「シャラシャラした」独特のノイズ感が出る。
- **設計上の対応：** 素材の基準BPMを **100** に揃えて集め、アプリのBPM選択肢を **85 / 100 / 115** の3段階に絞る（それぞれ -15% / 0 / +15%）。連続可変のスライダーは置かない。
- **未検証：** 実際にどこまで劣化が許容できるかは**耳で確認するまで断定できない**。Day 2 で必ず実音テストを行い、耐えられなければ「BPM固定（100のみ）」に落とす判断をする（→ 7章の決定ポイント D-1）。

### 4-2. キー（調）の統一

ループ素材は素材ごとにキーがバラバラ。何を重ねても成立させるには揃える必要がある。

- 素材収集時に**キーが明記されているものを優先**して集める。
- 揃わないものは `detune`（セント単位）で移調する。半音 = 100セント。
- 統一先は `実装計画.md` 6章の方針どおり **Cマイナー・ペンタトニック系**を基本とする。
- ドラム・パーカッションはキーの概念がないのでそのまま使える。**最初にドラムから集める**のが安全。

### 4-3. 「ジャンルの違いがわからない」問題への解答

これはループ素材方式に変えることで**自動的に解決する**。今の合成音版は「同じ音色で叩き方だけ変える」設計なので違いが出にくかったが、ジャズのウッドベースとロックのエレキベースは**素材そのものが別物**になる。作り直しの最大の利点はここ。

### 4-4. RFID入力の受け取り

HIDリーダーは「キーボード」として認識され、UIDを文字として打ち込んで最後に Enter を押す。つまり実装は**キー入力の蓄積とEnterでの確定**だけ。

```
keydown イベント
  ├ 数字・英字 → バッファに溜める
  ├ Enter      → バッファを UID として確定 → cards.json で照合 → 音を追加
  └ 一定時間(300ms)入力が途切れたらバッファを捨てる（人間のキー操作と区別する）
```

- **リーダーがなくてもテストできる：** キーボードで `0004512345` + Enter と打てば、リーダーからの入力と完全に同じ経路を通る。**これがこの1週間のテスト手段になる。**
- 二重読みガード：同一UIDの連続入力を **500ms** 無視する。
- 未登録UIDが来たら、進行役画面に「未登録：0004512345」と表示して**その場でコピーできる**ようにする（→ 到着日のUID登録が劇的に楽になる）。

### 4-5. 進行役画面（プレイヤーには見せない）

見せない前提なので、見栄えより**進行役が困らないこと**を優先する。

| 表示するもの | 理由 |
|---|---|
| 残り時間（大きく） | 進行の判断に要る |
| 今鳴っているパート一覧 | 「6つ上限で最古が抜ける」挙動の確認 |
| 直前の読み取りログ（UID・カード名・時刻） | 読み逃しの切り分け |
| 未登録UIDの表示＋コピーボタン | 到着日のUID登録作業そのもの |
| 音量マスター / 緊急停止 | トラブル時 |

## 6. D-Day（到着日）の作業手順

**目標所要時間：2〜3時間**

### ステップ1：リーダーの生存確認（10分）
1. PCに挿す。ドライバのインストールが始まらないことを確認（HIDなら不要）
2. **メモ帳を開く**
3. NFCシールを1枚かざす → 数字列が打ち込まれ、Enterが押されることを確認
4. ❌ 何も出ない／文字化けする場合 → 8章「リーダーがHIDでなかった場合」へ

### ステップ2：UIDの一括登録（30〜40分）
1. `output/live-app/` を起動し、進行役画面を開く
2. カードに貼る前のシールを1枚ずつかざす
3. 「未登録：xxxx」表示をコピーし、対応する楽器×ジャンルを割り当てる
4. 全枚数ぶん繰り返し、`cards.json` を保存
5. **シールに鉛筆で番号を振っておく**（貼り間違い防止）

### ステップ3：シールをカードに貼る（20分）
- **全カードで同じ位置（中央）に貼る。** 位置がばらつくと読み取り率が落ちる
- 貼ってから表面保護（D-3で決めた方法）を施す

### ステップ4：スロープの位置合わせ（30分）
1. Day 5 のスロープにリーダーを仮固定（読み取り面が上向き、カード面から2〜4cm）
2. カードを10回滑らせ、読み取り成功回数を数える
3. 10/10 になるまでリーダーの高さ・角度を調整する
4. ⚠️ **リーダー周辺に金属を使わない**（13.56MHzの磁界が乱れる）
5. 成功したら、その寸法を**記録してから**固定する

### ステップ5：箱本体の製作（40分）
- ステップ4で確定した寸法で箱を作る
- 投入口の高さは「カード厚 + 2mm」（2枚同時投入を物理的に防ぐ）
- ケーブル出口は背面下部に切り欠き

### ステップ6：DoD確認（20分）
- 2章のチェックリストを上から順に確認する

## 8. リスクと対策

| リスク | 起きること | 対策 |
|---|---|---|
| **CC0のループ素材が十分に見つからない** | 音の作り直しが完遂しない | **studio-app の音を初期状態として持っておく**。集まった楽器から順に差し替える。1つも見つからなくても Phase 1 は完成する |
| **タイムストレッチの音質が耐えられない** | BPM可変を諦めることになる | D-1 で早期に判断する。固定に落としても企画の本質（重ねて曲を作る）は損なわれない |
| **リーダーがHID出力でなかった** | メモ帳に何も出ない | 商品説明を再確認 → 専用ソフト前提の製品なら返品・交換を検討。**この判定を到着日の最初の10分でやる**のはそのため |
| **NFCシールとリーダーの規格が合わない** | かざしても反応しない | 13.56MHz / ISO14443A(NTAG213) の組み合わせのはず。両方の商品ページを到着前に再確認しておく |
| **シールを貼るとカードが厚くて詰まる** | 投入口を通らない | Day 5 のスロープ試作時に、**シール相当の厚み（0.1mm程度）＋保護材の厚みを足した見本**で通す |
| **音量バランスが決まらない** | 延々と調整して終わらない | Day 7 を予備日にしてある。それでも決まらなければ「全部同じ音量」で出す（後日調整できる） |
| **到着が予定より遅れる** | 手が空く | Day 7 以降は音の作り込みに充てる。作業が独立しているので手戻りはない |
