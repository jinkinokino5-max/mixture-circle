## 0. 結論（先に3行）

1. **次にやるのは「聴いて、気持ちよくないところを潰す」こと。** 数値上は設計どおり動いているが、良し悪しは耳でしか分からない。
2. 調整箇所は `music.js` と `engine.js` の**上のほうだけ**に集めてある。1か所ずつ動かして聴き比べれば足りる。
3. ゲームルール（配り方・遊び方）とRFID化は、音が決まってから。**順番を逆にしない。**

## 1. v2 から v3 で変えたこと（要約）

| 観点 | v2 | v3 |
|---|---|---|
| 枚数 | 20（4役割×5ジャンル） | **32**（4役割×8ジャンル） |
| 楽器 | 11 | **22**（カード1枚＝2〜3楽器） |
| 同時枚数 | 6固定 | **3/4/6/8/10 から選択** |

| 低音 | 単層 | **サブベース層を追加** |
| 動き | なし | **サイドチェイン・ポンピング（43%）** |
| 空間 | ほぼ乾き | リバーブ増量＋付点8分ディレイ＋ステレオ配置 |

## 2. Day 1：耳で聴いて詰める（最優先・半日〜1日）

**これをやらないと先に進めない。**

### 2-1. 聴く順番

1. `はじめる.bat` → BPM 104・無制限・同時6枚 で起動
2. **1枚だけ入れて聴く** — 32枚を1枚ずつ。「投入した瞬間が気持ちいいか」だけを見る
3. **同ジャンルで4枚揃える**（例：ファンクの `2` `W` `S` `X`）— そのジャンルらしいか
4. **ジャンルを混ぜる** — これが本番。破綻していなければ設計は成功
5. **同時枚数を 3 と 10 で比べる** — どちらが気持ちいいか。既定値を決める材料にする

### 2-2. 気になったときに触る場所

| 症状 | 触る場所 |
|---|---|
| 投入の一撃が弱い／強すぎる | `engine.js` `playImpact` の `0.34`（クラッシュ）と `0.55`（低音） |
| 合図音（ポーン）が目立ちすぎる／聞こえない | `engine.js` `playCue` の `[周波数, 音量, 減衰秒数]` の表。基音は `784`（G5） |
| ノリが重い／軽い | `engine.js` `schedulePump` の深さ `0.28 + 0.04 × 枚数` |
| 待たされる感じがする | 開始画面で「次の拍頭」を選ぶ。既定を変えるなら `app.js` `State.quantize` |
| 特定の楽器だけ大きい／小さい | `music.js` の各レイヤーの `gain` |
| 全体が暗い／シャリつく | `engine.js` `Bus.air` の `gain: 5` |
| 低音がもたつく | `engine.js` `Bus.mud` の `gain: -2.5` |
| フレーズが単調・くどい | `music.js` `CARDS[...].phrase`（小節を足す／減らす） |
| 和音の響きを変えたい | `music.js` `PROG` の `vc` と `lad` |

### 2-3. 完了の目安

- [ ] 32枚それぞれで「投入した瞬間」が気持ちいい
- [ ] ジャンルを混ぜても不快でない
- [ ] 同時枚数の既定値（3〜10のどれか）を決めた
- [ ] 「これなら人に見せられる」と自分で思える

## 3. Day 2：カードを絞る（半日）

**32枚は多すぎるかもしれない。** 実際に遊んでみて、使われないカード・区別がつかないカードを削る。

- [ ] 8ジャンルのうち、音を聴いて区別がつかないものは無いか
- [ ] 物理カードにしたとき、32枚は配りやすいか（3〜6人で1人5枚なら 30枚前後が上限）
- [ ] 削るなら**ジャンル単位**で削る（役割は4つとも必要）

> 増やすのは簡単だが、**遊べる枚数には上限がある。** ここは音を聴いてから判断する。
