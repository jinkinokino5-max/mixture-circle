04 — FIRST AID

詰まったときの処方箋

初心者が高確率で踏む地雷と、その場での切り分け手順。詰まってから読むのではなく、詰まる前に一度目を通しておくと復帰が速くなります。

ブラウザから音が出ない
  1. ブラウザは「ユーザーが操作するまで音を鳴らせない」仕様。画面上のボタンを押してから音を出す設計になっているか確認する。
  2. OS側の音量・出力デバイスを確認（イヤホンに出ていないか）。
  3. 開発者ツール（F12）の Console にエラーが出ていないか見る。
  4. AudioContext の状態を確認。suspended なら resume() を呼ぶ。
RFIDリーダーがカードを読まない
  1. まずメモ帳を開いてかざす。ここで文字が出なければアプリの問題ではない。
  2. カードとリーダーの距離（2〜4cm推奨）と、シールの貼り位置を確認。
  3. リーダーの近くに金属がないか。段ボールの中に金属クリップなどが混ざっていないか。
  4. 周波数帯が合っているか（13.56MHz のリーダーで 125kHz のタグは読めない）。
  5. USBハブ経由なら、PC本体のポートに直挿しして試す。
音がリズムからズレる / もたつく
  1. setTimeout や setInterval で発音していないか確認する。これは音楽用途では必ずズレる。
  2. オーディオの時計（AudioContext.currentTime／Tone.js の Transport）で未来の時刻を予約する方式に直す。
  3. 重い描画処理（DOM更新・アニメーション）が同じフレームで走っていないか。
  4. 同時発音数を減らして改善するなら、負荷が原因。
同じカードで音が二重に鳴る
  1. リーダーが1回の通過で複数回読んでいる。同一UIDを一定時間（500ms程度）無視するガードを入れる。
  2. すでに鳴っているパートを再投入したときの挙動を決める（無視／リスタート／音量アップ）。仕様として決めていないとバグに見える。
LEDが光らない
  1. 電源が来ているか（テスターで電圧を測る）。
  2. LEDの向き（極性）。長い足がプラス側。
  3. 抵抗を入れ忘れていないか。入れずに繋ぐとLEDが壊れる。
  4. NeoPixelは信号線の向きがある。テープの矢印の向きを確認。
  5. USBの電流で足りているか。多数のLEDを全点灯すると不足する。
マイコンにプログラムが書き込めない
  1. USBケーブルが充電専用でないか。データ通信対応品に替える。
  2. ドライバ（CP210x / CH340 など）が入っているか。
  3. シリアルモニタを開いたままだとポートが掴まれて書き込めないことがある。閉じる。
  4. ボード種別・ポートの選択が合っているか。
  5. 書き込み時にBOOTボタンを押し続ける必要があるボードもある。
コードを壊した / 前の状態に戻したい
  1. Gitでコミットしてあるなら戻せる。まず git status と git log で現在地を確認。
  2. コミットしていない変更を捨てるなら git restore <file>。
  3. まだGitを使っていないなら、今すぐ始める。これは学習コストではなく保険料。
何を作っていたか分からなくなった / やる気が切れた
  1. 実装計画の「完了条件（DoD）」を見る。次に満たすべき1行だけを見る。
  2. 15分でできる最小の作業に切り分ける。カードを1枚作る、UIDを1個登録する、でよい。
  3. 人に見せる。反応が返ってくると再点火しやすい。
  4. 制作過程の写真を見返す。進んだ量が可視化される。
予算が足りなくなった
  1. Phase 1（リーダー＋シール）だけで作品は成立する。Phase 2以降は「質の向上」であって必須ではない。
  2. スピーカー・PCは手持ちで代用。箱は段ボール。ここに金をかけるのは最後。
  3. 近所のファブ施設・大学の工房を調べる。設備を買わずに使える場合がある。
