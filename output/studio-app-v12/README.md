## 0-n. v30からの変更点（v31・2026-09-03〜）— メロディ列の非対称拡張（作り直し）

`stone-app-v30`をまるごとコピー。ユーザー依頼「メロディ列だけ1世界5枚→10枚に
増やし、bass/rhythm/chordは5枚のまま据え置く（非対称）」に着手した。

最初の実装（5つの共通「性格」を新設し、全18世界に同じ既定メロディを
フォールバックさせる案）は**ユーザーの指摘で撤回**した。「勝手に性格を
与えず、その世界にあった魅惑的なメロディを作ってほしい」という要望を受け、
以下の設計に作り直した。詳細は`PDCA_v31.md`参照。

- 「性格」の概念は撤廃。メロディ拡張は`ext1`〜`ext5`という**位置**でしか
  なく、曲名・説明・楽器・旋律は完全に**世界ごとの`extMelodies`が持つ**。
  世界がその位置を定義していなければ、その札はその世界には存在しない
  （他世界の内容へフォールバックしない。グレーアウトして押しても
  何も起きない）。
- パイロットとしてモータウン・久石譲の2世界を自分で作曲したのち、
  ユーザーから「もっと動きのあるメロディに」「残りはサブエージェントに
  分岐して」という指示を受け、**残り16世界を世界ごとに1体のサブエージェント
  へ並行分岐**させて作曲を完了。**全18世界**に、既存20枚と被らない5楽器の
  固有メロディ5枚（8分/16分中心の動きのある譜面）を実装した
  （絶対音名で作曲→ラダー番号へ機械変換→逆変換で一致確認、という
  既存の確立手順を全世界で踏んだ）。
- UI（`#gridExt`）は世界を切り替えるたびに曲名・説明を書き換える
  （`UI.refreshExt()`）。ミキサー・`allCardIds`（かくはん対象）にも接続済み。
  これでメロディ役割は全世界で5枚→10枚（4役割×5性格20枚＋メロディ拡張5枚＝
  25枚）になった。
- 実機・ブラウザでの再生確認は本サイクルでは未実施（次回最優先で行う）。

## 0-m. v17からv30までの変更点（2026-09-03〜）— 恒久PDCAサイクル 第12回〜第24回・目標到達

指示書`stone-app-v18/PDCA_指示命令まとめ.md`の到達目標「stone-app-v30まで
到達すること」を、恒久PDCAサイクルを13回積み重ねて達成した。各バージョンで

各回の詳細はそれぞれの`PDCA_vN.md`、全体の総括は`PDCA_v30.md`の

残り固有メロディの無い世界：`lofi`・`rocknroll`・`modernpop`の3つ
（次サイクル以降の候補）。

**この期間に確立した設計原則**：
- melody役割の作曲は、必ず先にそのコードのラダー配列（lad）に実在する
  音名を洗い出してから絶対音名で作曲し、Nodeスクリプトでラダー番号への
  変換→逆変換一致を確認する（v18で変換失敗を経験して確立）。
- bass役割はc（コード相対index：0=ルート/1=5度/2=オクターブ/3=3度）、
  chord・rhythm役割は`{s,v,l}`や`{s,p,v}`形式で書けるため、絶対音名の
  ラダー検証は不要（v23・v25・v26で確立）。
- リズムの型（ワン・ドロップ、四つ打ち、ラスゲアードの3-3-2、ファンク
  ベース）は進行に依存しないため4小節とも同一パターンで繰り返す。
- 新規定数の命名は既存world key（beatles/kaze/modal等）と紛らわしく
  ないか事前確認する（v20の教訓）。
- 1世界内で複数役割を同時に専用化することも可能（v28のfunkで実証：
  melody+bass）。

**その他の点検**：v22で全18世界のrhythm札（groove/drums kit）を試聴
5周目データに照らして点検したが、修正すべき問題は見つからなかった
（「グルーヴより楽器編成が支配的」という既存の結論と整合）。
card-gain.jsの定点観測は、v12の焼き込み以降この期間を通じて一度も
新しいユーザー操作データが見つからなかった。

## 0-g. v11からの変更点（v12・2026-09-03〜）— 恒久PDCAサイクル 第6回・既存カード見直し 第1弾

- **和音（CHORD）カードの既定音量を焼き込みで是正**：ミキサー画面の
  書き出し（`card-gain.js`）を見ると、5枚の和音カード全てがユーザーの

  一切変えず**、ミキサーを開かなくても最初から正しいバランスになるよう
  にした（Node検証で焼き込み前後の実効dBが完全一致することを確認）。

  saxophone/trombone等を「弱い楽器」として一律排除すること）は、
  今回は**見送った**。理由：(1)本番は常に2層以上の厚いミックスで
  試聴4周目の薄いミックスとは条件が違う、(2)試聴5周目（より新しい・
  より本番に近いデータ）ではサックスのソロが好評という逆の結果が出て
  いる、(3)`modal`世界などは史実に基づく意図的な楽器選定である
  ことがコード内コメントに明記されている。詳細な理由は`PDCA_v12.md`。

  試聴3周目のt8（ビッグバンドのホーン＝trumpet+bass-electric、全10リズムで★）、
  試聴4周目の楽器パレット上位（harp/guitar-electric/flute/xylophone）、
  試聴5周目の①グループ（3管ハーモニー・サックスソロがグルーヴ非依存で★）を
  「押し」＝3管ハーモニーの一斉射撃、「歌」＝サックスのソロ、という形に落とし込んだ。
  詳しくは`music.js`の`motown`世界の冒頭コメントを参照。
- **GROOVES（土台のビート）に4種追加**：`soulRevue`／`tambourine`／`doubletime`／
  `crescendoBig`。試聴5周目で好評だったグルーヴの質感（ソウル・レビュー、
  タンバリン強調、ダブルタイムのハット、壮大なクレッシェンド）を、既存の
  グルーヴには無かった選択肢として追加。モータウン世界は`soulRevue`を採用。
- `はじめる.bat`／`音源をダウンロード.bat`：v5から未修正だった`timeout`コマンドの
  不具合（非対話環境で`Input redirection is not supported`になる）を`ping`ベースの
  待機に修正。文字化けの原因だった全角文字も英数字に置き換えた。
- 試聴で使った「音楽カード_検討記録_引継ぎ.md」もこのフォルダにコピー済み
  （経緯を追うための参照用。内容自体はv5時点のまま）。

**留意点**：PHRASES（歌える形・リズムの実際の音符）は「世界」ではなく
「キャラクター（軸/歌/押し/刻み/彩り）」に紐づく共有インフラで、
全世界が同じ4小節フレーズを共有する設計（9章コメント参照）。
そのため音楽カード試聴6〜8周目で作った具体的な旋律（固有の4小節メロディ）は、
この構造上そのままでは「1つの世界だけの専用メロディ」にできない
（変更すると全12〜13世界のメロディが一斉に変わってしまう）。
今回は無理に押し込まず、**新しい「編成（世界）」の追加**という
安全側の実装にとどめている。旋律そのものを世界ごとに変えたい場合は、
PHRASES構造の拡張（キャラクター追加や世界ごとのフレーズ差し替え機構）が
必要になるため、着手前に方針を相談したい。

**「かくはん型」への再設計。**（2026-09-01作成、v5時点の記述）

v4までは「石1個＝特定の音（性格×役割 or スタイル×世界）」という1対1の対応だった。
石の重さ判定の精度がどうしても安定しない問題が続いたため、本人と議論のうえ、
**石の重さ変化を「特定の音のON/OFFスイッチ」ではなく「セッション全体をゆらす
撹拌（かくはん）操作」として再定義した**。石を置く/取るのは"何が起きるか
分からないが、何かが起きる"きっかけであり、狙った編集（この音を消す、など）は
諦める代わりに、精度が多少悪くても体験が破綻しない設計にしている。

`stone-app-v4` をベースに、識別（どの石か）に関わる部分を丸ごと削除した。

---

## 1. v4からの変更点（重要）

| | v4 | v5（このフォルダ） |
|---|---|---|
| 石の意味 | 1個＝特定の音（性格×役割 or スタイル×世界）に1対1対応 | 意味を持たない。重さの**増減**だけを見る |
| 重さの識別 | レンジ丸め（`rangeSize`）で登録済みの石と照合 | **廃止**。「増えた/減った」の二値のみ |
| 石の登録 | 「石を管理…」モーダルで性格×役割を1個ずつ登録 | **廃止**（登録という概念自体がない） |
| 増えたとき | 対応する札を1枚だけ挿入 | 確率的に「①ランダムに札を1枚追加(80%)／②世界を変える(15%)／③揺らす(5%)」のいずれか |
| 減ったとき | 対応する札を1枚だけ除去 | 確率的に「①ランダムに札を1枚外す(80%)／②標準の世界へ戻す(10%)／③揺らす(10%)」のいずれか |
| 石が全部なくなったら | 何もしない（石が無い＝無音のまま） | **自動リセット**：鳴っている音を全部フェードアウトし、世界も標準に戻す |
| 精度への依存 | 高い（レンジ幅・ノイズ閾値の調整が常に必要だった） | 低い（「増えた/減った」さえ検出できればよい） |

確率の比率は`app.js`の`handleStoneIncrease`/`handleStoneDecrease`にそのまま数値で
書いてある（`pickWeighted([[80, ...], [15, ...], [5, ...]])`の形）。実際に触ってみて
体感で調整してよい。

**据え置き（v4から無変更）**：
- 「置いてよいタイミング」のランプ表示（「石に触れないで」/「石を追加・除去可能」、
  最低1.2秒＋安定するまで待つクールダウン）
- ドリフト追従（Holt法）・異常値ガード・Web Serial接続・手入力シミュレーター
- 「揺らす」演出はengine.jsの`playImpact`を再利用した単純な音量の凹みのみ
  （新しい合成音は作っていない）

**削除したファイル・機能**：
- `stone-registry.js`（石の登録レジストリ）→ v5には存在しない
- 「石を管理…」モーダル一式（性格/役割の登録フォーム・レンジ幅変更・重さ計測）
- `StoneMatcher.decide()`/`toRange()`/`findConflicts()`の呼び出し
  （`stone-matcher.js`自体は`createSettleTracker`のために残してあるが、
  これらの関数はもうどこからも呼ばれていない）

## 2. 動かし方は2通り

| | 用途 | 起動方法 |
|---|---|---|
| **デスクトップアプリ版**（`desktop/`） | 専用ウィンドウで動く。ただし本フォルダには`node_modules`を含めていないため、**初回は`desktop`フォルダで`npm install`が必要** | `npm install` の後 `desktop/はじめる.bat` |
| ブラウザ版（このフォルダ直下） | 動作確認・検証用。Chromeで開くだけで試せる | `はじめる.bat` |

---

## 3. ブラウザ版の使い方（検証用）

1. `音源をダウンロード.bat` を**最初の1回だけ**実行する（要ネット接続・要Node.js）
2. `はじめる.bat` を実行する → ブラウザが開く
3. 画面下の「石パネル」で、**手入力**（`手入力で重さを試す`）に数値を入れて「この重さを反映」を押す
4. 最初に基準の重さができる（何もしなくてよい）。そこから数値を大きく変えると
   「増えた/減った」が検出され、何かが起きる（音が増える・世界が変わる・揺らぐ、等）
5. 基準の重さ付近に戻すと、自動的にリセットされる

キーボード操作も生きている（性格カードは `1`〜`5`/`q`〜`t`/`a`〜`g`/`z`〜`b`、
スタイルカードは `6`〜`0`/`y`/`u`/`p`/`i`/`o`/`h`/`j`）ので、石の代わりに直接
試すこともできる。
