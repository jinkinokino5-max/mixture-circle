# stone-app-v12 PDCAログ（第6回）— 既存カードの見直し 第1弾

恒久PDCAサイクル第6回。今回からユーザーの指示で「既存の音楽カードも
恐れず改変してよい」というスコープが追加された。

## Plan（計画）
ユーザー指示（試聴1〜5周目の傾向：①コード進行はほぼ無視してよい
②楽器の組み合わせとリズムが支配的③強い当たり楽器＝トランペット/ホーン・
ギター・harp/xylophone/guitar-electric/flute④弱い/外れやすい楽器＝
organ単体・violin単体・saxophone単体・trombone単体・各種シンセpad/organ/
bell単体）を基準に、既存17世界のmelody札を機械的に洗い出した。

**重要な判断（機械的な楽器差し替えを見送った理由）**：
洗い出しの結果、organ/violin/saxophone/trombone等が「主役（accent無しの
1枚目）」として使われている箇所が26件見つかった。しかしコードを詳しく
読むと、
1. これらは全て2レイヤー構成で、accentレイヤーに強い楽器（piano/
   guitar-electric/trumpet等）が添えられている。試聴4周目の「弱い楽器」
   判定は**単独リード+ベースのみの薄いミックス**での判定であり、
   本番の常に2層以上ある厚いミックスにそのまま適用できるとは限らない。
2. サックスは試聴4周目では0/5だったが、試聴5周目（同じ楽器を実際の
   バンド編成＋グルーヴで再テスト）では「サックスのソロ」が6/10で
   好評——**より新しく・より本番に近い条件のデータの方が優先**
   （引継ぎ記録3章5項の原則どおり）。motown/rocknrollのサックスソロは
   むしろこのデータに裏付けられている。
3. `modal`（マイルス/エヴァンス）世界はコード内コメントで「カインド・
   オブ・ブルーの六重奏を再現するため、ギターもシンセも意図的に
   入れていない」と明記されている。サックス/トランペット中心の編成は
   **史実に基づく意図的な選択**であり、「弱い楽器」判定を機械的に
   当てはめて壊すべきではない。
同様の理由で`swing`（ビッグバンド）や`reggae`（管のスカンク）も
ジャンルの根拠がコード内コメントに明記されている。
→ **今回は楽器の機械的な差し替えを見送り、代わりにもっと確度の高い
既存の不満のシグナルを探すことにした。**

## Do（実行）
`card-gain.js`（ミキサー画面がユーザーの実際の操作から書き出したファイル、
2026/9/3 02:13時点）を読み直したところ、**5枚の和音（CHORD）カードが
全て-8.5〜-9dBもユーザーの手で下げられていた**（color/core/push/sing-chord
が-8.5、drive-chordが-9）。全5枚が同じ方向に近い量だけ動いている＝
偶然ではなく、`ROLES.chord.gain`の既定値(-5dB)そのものが高すぎたと判断。

1. `music.js`の`ROLES.chord.gain`を`-5`→`-13.5`に変更（実測オフセットの
   平均-8.6を反映）。
2. `card-gain.js`から、焼き込みで0になった4枚（core/sing/push/
   color-chord）のオーバーライドを削除。drive-chordだけ元が-9とさらに
   0.5dB深かったので、その差分`-0.5`だけ残した。
3. Node検証で、焼き込み前後の実効音量（ROLES.gain + オーバーライド）が
   5枚すべて完全一致することを確認（下記Check参照）——**この変更は
   聞こえ方を一切変えず、「ミキサーを開かなくても最初から正しい音量」
   にするだけの変更**。

## Check（確認）
- `node --check music.js` / `node --check card-gain.js` → 構文OK
- 焼き込み前後の実効dB比較（Node）：
  - color-chord: 旧-13.5 → 新-13.5（一致）
  - core-chord:  旧-13.5 → 新-13.5（一致）
  - drive-chord: 旧-14   → 新-14（一致）
  - push-chord:  旧-13.5 → 新-13.5（一致）
  - sing-chord:  旧-13.5 → 新-13.5（一致）
  → JSON文字列比較で完全一致（match: true）
- 構造整合性チェック：WORLD_ORDER 17件・重複なし、missingVoice 0、
  missingGroove 0（世界の中身は今回変更していないので当然だが再確認）
- 全コアJSファイル（music.js/app.js/engine.js/mixer.js/card-gain.js/
  samples.js/cards.js/server.js）で`node --check`構文OK
- 実際に鳴らしての確認は今回省略（ユーザー指示により不要）

## Act（次への反映）
- 「既存カードの見直し」は、勘や一般論（試聴4周目の単独楽器評価）で
  機械的に楽器を差し替えるより、**ユーザー自身が実際に使って書き出した
  ミキサーのデータ**の方がはるかに確度が高いと分かった。次回以降も
  card-gain.jsの変化を定点観測し、同じように「揃って動いている」項目が
  あれば同じ要領で焼き込む。
- 今回はchordのみ対応。melody（core-melody+10.5/drive-melody+7.5・
  push-melody-1）とbass（core-bass-1・sing-bass-1）は、5枚中1〜2枚しか
  動いていない＝キャラクター固有の事情の可能性が高く、ROLES側の
  一律変更はまだ見送った。仮に次回以降さらにデータが増えて全キャラ
  揃って動くようなら、同様に焼き込みを検討する。
- 楽器そのものの差し替えは、今回は見送ったが完全に不要と判断した
  わけではない。次回以降、①ジャンル的な根拠がコード内コメントに
  無い世界（beatles/citypop/house等の汎用ポップ系）②試聴4/5周目
  どちらのデータにも支持が無い組み合わせ、に絞って再検討する。
- 次のサイクルの候補：
  a) 残りクラスタ（②クールジャズ/ピアノトリオ、⑨サンシャインポップ）
  b) card-gain.jsの melody/bass 側も、今後の実測データが増えたら焼き込み
  c) ジャンル的根拠のない世界の楽器選定を、上記の絞り込み基準で再点検
- 次はどれかを実施し、`stone-app-v13`として切り出す。
