# STUDIO PULSE II — 音と楽器を詰めた版（studio-app-v5）

v4（ROLE × INSTRUMENT）の**骨格はそのまま**に、
「**どんな音と楽器を用意すれば気持ちよくセッションできるか**」だけを追求した版。

カードは **ROLE（曲の中で何をするか）× INSTRUMENT（何の音でするか）× VARIATION（その楽器で何を弾くか）**。
調・コード進行・グルーヴをエンジンが握るので、何と何を重ねても必ず噛み合う。

**40楽器 × 3つの弾き方 ＝ 120枚。**

---

## 1. 使い方

1. **`音源をダウンロード.bat`** を最初に1度だけ実行（インターネット接続が必要／約43MB）
2. **`はじめる.bat`** をダブルクリック → ブラウザが開く（ポート **8770**。v4 は 8769 なので同時に動かせる）
3. 「はじめる」を押して、キーボードでカードを重ねる

※ `index.html` を直接ダブルクリックしても動くが、ブラウザの制限で音源が読めず全パート合成音になる。必ず `はじめる.bat` から開く。

---

## 2. いちばん大事なところ ── 3つの「変化」

ひとつの楽器に3つの弾き方がある。3つはランダムな別フレーズではなく、**役割がはっきり違う**。

| | 名前 | 中身 | いつ使うか |
|---|---|---|---|
| **1** | 基本 | その楽器の代表的な弾き方 | まずこれ |
| **2** | 余白 | 音数が少なく、音符が長い | すでに賑やかなとき、**下に敷く** |
| **3** | 刻み | 音数が多く、音符が短い | すでに疎なとき、**上に乗せる** |

1小節あたりの平均音数は **基本 8.6 / 余白 2.9 / 刻み 15.8**。

これは飾りではなく、v5 でいちばん困っていた「**重ねるほど団子になる**」を正面から解く仕掛け。
いま鳴っているものが賑やかなら 2 を、寂しいなら 3 を選べば噛み合う。

**キーボードでは同じキーを押すたびに 1 → 2 → 3 → 止まる と巡回する。**
画面の数字ボタンを直接クリックしてもよい。
物理カードでは変化ごとに別々のカードになる（同じ楽器の別の変化をかざすと、足されずに差し替わる）。

---

## 3. 操作

| 操作 | 内容 |
|---|---|
| `1`〜`0` | MELODY（曲の顔）10楽器 |
| `Q W E R T Y U I O P` | CHORD（曲の空間）10楽器 |
| `A S D F G H J K L ;` | BASS（曲の足元）10楽器 |
| `Z X C V B N M , . /` | RHYTHM（曲の動き）10楽器 |
| **同じキーをもう一度** | **変化 1 → 2 → 3 → 止まる** |
| **スペース** | **ビルドアップ＆ドロップ**（2小節かけて持ち上げ、次の小節頭でクラッシュとともに落とす） |
| `↑` `↓` | ENERGY（静／走／熱） |
| `Tab` | コード進行を切り替え（夜／陽／呪／都） |
| `Backspace` | 最後に入れた1枚を戻す |
| `Esc` | 終了（録音を書き出す） |

同時に鳴らせる枚数：**MELODY 2 / CHORD 2 / BASS 1 / RHYTHM 3**。

## 4. 楽器一覧（40楽器＝120枚）

### MELODY（曲の「顔」・同時2枚）
ピアノ／エレキギター／ナイロンギター／サックス／クラリネット／フルート／ヴァイオリン／トランペット／トロンボーン／シンセリード

### CHORD（曲の「空間」・同時2枚）
ピアノ／アコギ／カッティング／オルガン／ハルモニウム／ハープ／ストリングス／ブラス／ホルン／シンセパッド

### BASS（曲の「足元」・同時1枚）
エレキベース／ウッドベース／チェロ／チューバ／バスーン／オルガンベース／ピアノ（低音）／シンセベース／ファズベース／サブベース

### RHYTHM（曲の「動き」・同時3枚）
| キック持ち（土台になる・6楽器） | 薄い層（キック無し・どれにでも重ねられる・4楽器） |
|---|---|
| 生ドラム／ブレイクビーツ／四つ打ち／ドラムマシン／80sマシン／ロックキット | 木琴／シェイカー／ボンゴ／ライド |

シンセ系5楽器（シンセリード／シンセパッド／シンセベース／ファズベース／サブベース）以外はすべて**実録音**。
画面の各カード右上に「実録音／合成音」が出る。

**音源はこれで打ち止め。** 公開されている tonejs-instruments の全20楽器・Tone.js の全12ドラムキットを
**すべて使い切っている**（実在をHEADリクエストで1音ずつ確認済み・2026-08-13時点）。
これ以上増やすなら、別のライセンス音源を持ち込む必要がある。

ドラムはバリエーションごとに**キットそのものを差し替える**ことがある（例：ドラムマシンの 1/2/3 は CR78 / KPR77 / 4OP-FM）。これで12キットを余さず使っている。

## 5. ドラムの語彙

`music.js` の `drum` に書ける項目：

| 記号 | 意味 | 効果 |
|---|---|---|
| `k` `s` `h` | キック／スネア／ハイハット | v4 から |
| `t` `t2` `t3` | タム（高→低） | フィルが「下りていくタム回し」になる |
| `oh` | オープンハイハット | 裏拍が伸びて前へ押される |
| `rd` | ライド | 刻みが金物になり、音数を増やしても濁らない |
| `cr` | クラッシュ | `bar % crEvery === crPhase` の小節だけ。小節頭で「開ける」 |
| `h3` `ghost` | ENERGY 3 の裏／小さいスネア | v4 から |

クラッシュ／ライド／オープンハットは**公開音源側に1枚も存在しない**ため、`samples.js` の `makeCymbals()` が `Tone.MetalSynth` で合成している（`tom2` `tom3` は実録音）。

## 6. 音量はどうやって決めたか（実測）

**耳ではなく、実際に音を書き出して測って決めた。**

`node-web-audio-api` で本物の mp3 をデコードし、120枚それぞれのパターンを4小節ぶん
`OfflineAudioContext` で合成して、**LUFS**（ITU-R BS.1770 の K特性ラウドネス、ゲート付き）で測っている。
単純な RMS だと低音が過大評価されるうえ、音数の少ない「余白」変化が休符ぶんだけ不当に小さく出る。
ゲート付き LUFS なら「鳴っているあいだの大きさ」で公平に比べられる。

音量は3段構えになっている。

| 段 | 何を吸収するか | 決め方 |
|---|---|---|
| **① 音源の録音レベル差** | ピアノは大きく録れていて、フルートは小さい | `samples.js` が読み込み時に実測してそろえる（自動・±14dBまで） |
| **② 楽器の存在感** | この楽器をどのくらい前に出したいか | `music.js` の `sound.gain`。書き出して測り、ROLE の基準値に合わせた |
| **③ 変化ごとの差** | 音数の多い「刻み」は同じ gain でも大きく聞こえる | 各 variant の `trim`（±6dBまで）。実測から自動計算 |

`trim` は**そろえるためだけ**の補正で、音量を盛る手段ではない。
±6dB で足りなかった4枚は trim ではなくパターン側を直した（単音を2音にする、キックを減らす等）。

### 実測の結果

```
                 ROLE 内の基準からのズレ（LUFS）
MELODY  基準 -30.4    全10楽器が  -0.2 〜 +0.8   （最大差 1.0dB）
CHORD   基準 -37.9    全10楽器が  -1.0 〜 +0.3   （最大差 1.3dB）
BASS    基準 -26.3    全10楽器が  -1.1 〜 +2.7   （最大差 3.8dB）
RHYTHM  基準 -26.6    土台6楽器が -0.2 〜 +1.2   （最大差 1.4dB）
                      薄い層は意図的に約 -6dB（重ねる前提の層なので）

変化1/2/3 のあいだの音量差： 平均 0.23dB（着手前は 5.47dB）
```

40楽器のうち **30楽器の gain を実測にもとづいて直した**。着手前は最大 10dB 以上ずれていた。

ブラウザのコンソールで **`studioLevels()`** と打つと、①の実測補正値の一覧が出る。

## 7. ファイル構成

| ファイル | 役割 |
|---|---|
| `music.js` | 音楽そのものの定義（調・コード進行・40楽器×3変化・演奏パターン） |
| `app.js` | 音響エンジンと画面（Tone.js の配線、パート、ドロップ、ビジュアライザ） |
| `samples.js` | 実録音の読み込み／ラウドネス実測／シンバル合成／楽器の生成 |
| `fetch-samples.js` | 音源のダウンロード（`音源をダウンロード.bat` から呼ばれる） |
| `cards.js` | RFID の UID とカードIDの対応表（120枚ぶんのIDが全部書いてある） |
| `server.js` | Python が無い環境用の簡易サーバ（ポート 8770） |

楽器を増やす／パターンを直すときは **`music.js` だけ**を触ればよい。`app.js` は音の出し方しか知らない。

`music.js` の構造：

```
INSTRUMENTS[楽器ID] = {
  label, sound: { ... gain はここに1つだけ ... },
  variants: [ {tag, trim, pat, patB}, {...}, {...} ]
}
        ↓ 起動時に展開
CARDS['楽器ID-1'], CARDS['楽器ID-2'], CARDS['楽器ID-3']
```

`sound` を楽器ごとに1つだけ持つのが肝で、**「ギター1は良いけどギター3だけ妙に大きい」が構造的に起きない**。

---

## 8. RFIDリーダーが届いたら

1. メモ帳を開いてタグをかざし、打ち込まれる UID を控える
2. `cards.js` の `CARD_MAP` に `'UID': 'カードID'` の形で書く（120枚ぶんのIDはそのファイル内にコメントで全部ある）
3. そのまま `はじめる.bat` で開けば、かざした瞬間に音が入る（アプリ側の変更は不要）

物理カードは **1枚 = 1つのID**。「ギター」は3枚のカードになる。

## 10. 確認済み／未確認

**確認済み**（すべて `node` 上での自動検証。検証スクリプトはこのフォルダには含めていない）

- 120枚すべてが16小節まわして発音し、例外が出ないこと（実録音経路・合成音フォールバック経路の両方）
- 全カード × 4進行 × 8小節の総当たりで、音名の解決に破綻がないこと
- サンプラーの要求音域と実際の音源の音域の突き合わせ（移調が6半音を超える箇所は解消済み）
- **3つの変化の約束が守られていること**：変化2は必ず変化1より疎、変化3は必ず変化1より密
- 同じキーを押したときの巡回（1→2→3→止まる）と、同じ楽器が2枚同時に鳴らないこと
- クラッシュ・ライド・オープンハット・タム2/3 がすべて実際に発火すること
- **音量（第6節）**。パート単体で 0dBFS を超えるカードは無し

**未確認 ── 実際に耳で聴いた印象**

以下は測定では詰め切れないので、聴いて直す余地がある。

1. **合成シンバルの音量**。ライドだけのカード（`rhythm-ride`）は測定上まだ基準より 14dB 低い。
   ただしこれは測定側の限界で、`Tone.MetalSynth` を Node 上で再現できず**帯域ノイズで近似**しているため、
   実際より小さく出ている可能性が高い（同じ理由で他のカードのクラッシュ／オープンハットも過小評価のはず）。
   **この1つだけは耳で確かめて `samples.js` の `makeCymbals()` の数値を詰めてほしい。**
2. **合成音5楽器**（シンセ系）。オシレータで近似して測っているので、実録音ほど精度は高くない。
3. **120枚それぞれのパターンが音楽的に良いか。** 数は揃えたので、聴いて削るのはこれから。
4. フレンチホルンは音源の C4 と D5 の間が14半音あいている。低い側だけ使うようにしてあるが、
   進行によっては補間の薄い音が出る可能性がある。
