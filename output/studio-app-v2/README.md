# ミクスチャー・サークル STUDIO v2 — ROLE × INSTRUMENT × GENRE 版

`reference/アイデア2.txt` `reference/音楽カード設計1.txt` `reference/音楽カードのサウンド設計1.txt`
で採用された **カード ＝ ROLE × INSTRUMENT × GENRE** の設計を実装したアプリ。

既存の `output/phase0-app`（合成音）・`output/studio-app`（本格音源・楽器×ジャンル24枚）とは
**別の第3のアプリ**として作ってある。既存2つには手を入れていない。

## v1（`output/studio-app`）との違い

| | v1（studio-app） | v2（これ） |
|---|---|---|
| カードの構造 | 楽器 × ジャンル | **ROLE × GENRE**（楽器は自動で決まる） |
| 枚数 | 6楽器 × 4ジャンル ＝ 24枚 | 4 ROLE × 5 GENRE ＝ **20枚** |
| ジャンル | ジャズ／ロック／クラシック／エレクトロ | 左記＋**ポップ** |
| 楽器 | 全ジャンル共通の6楽器 | **ジャンルごとに代表楽器が変わる**（全11種） |
| 和声 | 1つの和音の上を回るだけ | **Cm → A♭ → E♭ → B♭ の4小節進行** |
| フレーズ | 全パート1小節ループ | **2〜4小節の楽句**（ドラムは4小節目にフィル） |
| 拍の同期 | 投入した拍からパターン開始（小節とズレる） | **常に小節頭から数える**（いつ入れてもズレない） |
| カードID | `<ジャンル>-<楽器>` 例 `jazz-piano` | `<ジャンル>-<役割>` 例 `jazz-chord` |
| ポート | 8766 | 8767（3つ同時に立ち上げられる） |

**音源ファイルは v1 と同じものを使い、鳴らし方（旋律・和音・リズム・奏法）は全部作り直してある。**

## 使い方

1. **`音源をダウンロード.bat`** をダブルクリック（**最初の1回だけ**・約17MB・要ネット接続・要 Node.js）
2. **`はじめる.bat`** をダブルクリック → ブラウザが開く
3. 「本格音源 121 個を読み込みました」と出たら準備完了
4. キーを押す（またはマスをクリック）すると、**次の拍頭から**その音が加わる

音源を落とさずに始めることもできる。その場合は全パートが合成音になる。

## キー配置

**行＝ROLE（役割）／列＝GENRE（ジャンル）**。キーボードの並びがそのままグリッド。

| | ロック | ジャズ | クラシック | エレクトロ | ポップ |
|---|:---:|:---:|:---:|:---:|:---:|
| **MELODY** | `1` | `2` | `3` | `4` | `5` |
| **BASS**   | `Q` | `W` | `E` | `R` | `T` |
| **RHYTHM** | `A` | `S` | `D` | `F` | `G` |
| **CHORD**  | `Z` | `X` | `C` | `V` | `B` |

`Backspace` 最後の音を消す／`Esc` 終了／マスをクリックでも投入できる。

## 「破綻しない濁り」を作っている5つの仕掛け

企画書は「濁った混沌も価値」とするが、何をしても不快では体験にならない。

1. **コード進行の共有** — 全パートが Cm → A♭ → E♭ → B♭ を共有する。BASS と CHORD は進行を追いかけて音が変わる
2. **メロディの音階** — Cマイナー・ペンタトニックのみ。上の4つの和音すべてに対して外れない音だけで出来ている
3. **役割による周波数の住み分け** — BASS＝低域／CHORD＝中域／MELODY＝中高域／RHYTHM＝全域。**役割が違えば帯域が違う**ので重ねても団子にならない（v1 は楽器ごとに手で帯域を割り振っていたが、v2 は役割そのものが住み分けになっている）
4. **同時発音数の上限** — 最大6パート。7つ目を入れると最も古いパートがフェードアウトして抜ける
5. **拍頭への同期** — 投入した瞬間ではなく次の拍頭（または小節頭）から鳴る。しかもパターンは常に小節頭から数えるので、いつ入れても拍子が揃う

## 実装済みの細則

| ルール | 値・挙動 |
|---|---|
| 同時発音パート数 | 最大6。7つ目で最古がフェードアウト |
| 同じカードの重複投入 | 無視（「その音はもう鳴っています」と表示） |
| 二重読みガード | 同一カードの再入力を 500ms 無視 |
| 音量の自動調整 | パート数が増えるほど各パートを下げ、合計音量を一定に保つ |
| BPM | 70〜150（既定 96） |
| 終了処理 | 制限時間で自動終了、余韻を残して止め、録音を再生・保存できる |

## 音や譜面を調整したいとき

`app.js` の上から順に、独立して触れるようになっている。

- **`PROG`** … コード進行そのもの。ここを変えると全パートの響きが変わる
- **`ROLES`** … 役割ごとの**帯域**（`hp`/`lp`）・**基準オクターブ**・音量・残響の量
- **`VOICES`** … 楽器ごとの音源名とアタック／リリース
- **`CARDS`** … **20枚ぶんの譜面**。`phrase` は「小節の配列」なので、小節を足せばフレーズが長くなる
- **`MAX_PARTS`** … 同時発音数の上限

**音量バランスが気になったら各カードの `gain` を触る。** 実録音は音源ごとに録音レベルが違うので、
ここは実際に聴きながら合わせるのが前提の値になっている。

## 動作確認済みのこと

Chrome で実際に起動し、マスター出力を実測して確認した。

- 音源 **121個** の読み込み（エラーなし）。シンセ3種以外はすべて実録音で鳴ること
- **全20枚が実際に発音すること**（4小節ぶん再生して発音回数を計測。0回のカードなし）
- 発音密度が設計どおりであること（例：エレクトロのメロディ60回＝16分連打／クラシックのベース7回＝伸ばす音）
- 全20枚 × 全小節が生成する音名が、各音源の実在音域に収まっていること（音域外0件）
- **小節の途中で投入してもパターンが小節頭から数え直され、拍がズレないこと**（31回の発火で食い違い0件）
- 同時6パート上限と、7つ目投入時に最古が抜けること
- 同じカードの二重投入が無視されること
- 終了時に録音（.webm）が生成され、再生・保存できること

**未確認：** 音量バランスと音色の善し悪し、20枚を組み合わせたときの音楽的な良し悪し。
これは実際に耳で聴いて判断する必要がある（→ ロードマップ Day 1）。
