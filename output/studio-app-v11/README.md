# ミクスチャー・サークル v11

**「自分の録音カード」を足した版。**
セッションの途中でマイクに向かって歌う・声を出す・手拍子などを録ると、
その場でカードになる。20枚・12枚とは別枠（MYCARD、水色）で、
他の札と同じように出し入れできる。

`output/studio-app-v10` を複製して作った。v10 には手を入れていない（比較用に温存）。

## 0. v10 → v11 で足したもの（自分の録音カード）

### 0-1. 何ができるか

- 画面下の「＋ 録音する」（または <kbd>N</kbd> キー）から、1／2／4小節を選んで録音する
- 録った音は**自動でいまの世界の音階へ寄せられる**（自動ピッチ補正。ON/OFF可）。
  歌が音痴でも、ラップの語尾がフラットでも、いまの調に馴染む音へ寄る
- でき上がったカードは、他の札とまったく同じに**出す・外す・世界をまたいで鳴り続ける**
- セッション中に最大8枚まで録れる。いらないものは削除できる

### 0-2. 自動ピッチ補正の中身（pitchcorrect.js）

本物のスタジオのオートチューンではない。録音を短いフレームに割り、
各フレームの基本周波数を自己相関（YIN法の簡易版）で推定し、
**いまの世界の音階（メロディカードが使う「梯子」＝ `WORLDS[].prog[].lad` の和集合）**
に一番近い音へ、粒（グレイン）ごと読み出す速さを変える方式で寄せている。
フォルマント（声の質感）は保持しないので、寄せる幅が大きいと声質が変わるが、
「何を重ねても破綻しない」というこのアプリの目的には十分な精度になっている。

無音・子音・パーカッシブなフレームは検出を棄却してそのまま通す
（RMSしきい値0.006、YINのしきい値0.18）ので、
息づかいや手拍子までピッチが暴れることはない。

**Node上で確認したこと**：
- 440Hzの正弦波1フレームに対し、検出周波数 440.5Hz（誤差0.1%）
- 300Hzの正弦波1秒ぶんを「音階＝Cのみ」に強制補正すると、
  出力の検出周波数が257.7Hz（目標267Hz＝300Hzから-2半音）へ移動することを確認
- 1秒ぶんの補正処理が約120ms（ブラウザのメインスレッドで実行するため、
  録音後に「補正しています…」の表示を1フレーム描画してから重い処理に入る）

### 0-3. 録音ループの作り方（record.js）

- 録音の開始は拍に合わせない。押した瞬間から録り始める
  （「重ねたときに気持ちよくループするか」のほうが「録り始めが拍の頭かどうか」より
  体感に効くため、後者は割り切って捨てている）
- 録音の長さは、いまのテンポでの小節数ぴったりに**強制的に丸める**
  （録音デバイスの開始・停止はミリ秒単位でしかそろわないため、丸めないと
  ループのたびに他の札から少しずつズレていく）
- 継ぎ目に12msのフェードをかけ、ループ時のクリックノイズを消す
- 世界（スタイルカード）を切り替えても、自分の録音カードは**楽器を持たない
  ＝作り直す必要がない**ので、鳴らしたまま持ち越される
  （役割カードだけがその世界の編成で作り直される）

### 0-4. 既知の制約

- **BGMのマイクへの回り込みは完全には防げない。** 録音中はBGMを自動で少し
  下げ、ブラウザのエコーキャンセルも有効にしているが、スピーカー再生だと
  混ざる。**ヘッドホンでの録音を推奨**（画面にも明記した）
- **本物のフォルマント保持オートチューンではない。** 大きく音程を動かすと
  声質が変わる（ロボットっぽくなる）。これは仕様
- 録音は**セッション内のみ**（ページを再読み込みすると消える）。保存・共有は
  今回のスコープ外
- マイクの利用には安全なコンテキストが必要（`はじめる.bat` の
  `http://localhost` は対象。ファイルを直接開く運用では使えない）

- **32枚** ＝ 重ねる札 **20枚**（4役割 × 5性格）＋ 世界を決める札 **12枚**
- **13の世界**（標準・ビートルズ・藤井風・マイルス＆エヴァンス・久石譲・
  シティポップ・ダンス（四つ打ち）・ローファイ・
  **ファンク・ハードロック・レゲエ・フラメンコ・ビッグバンド**）が
  それぞれ **20枠ぶんの楽器編成を丸ごと持っている**
- **土台のビートも世界が持つ**（v10）。
  札を1枚も出していなくても、その世界のグルーヴが鳴っている
- **札ごとの音量を、聴きながら決められる**（ミキサー画面。<kbd>M</kbd>。9-b章）
- 同時に鳴らせる枚数は開始画面で 3/4/6/8/10/**無制限** から選べる（スタイル札は枚数に含まれない）
- **鳴っている札をもう一度タッチすると、その音が外れる**

> **v10 で足した3枚と v11 で足した5枚は、実物のRFIDカードをまだ登録していない。**
> キーボードの `0` `Y` `U` `P` `I` `O` `H` `J` では今すぐ遊べる。カードを使うときは
> `register.html` で登録して `cards.js` を貼り替えること。

## 0-0. v10 → v11 で変えたこと（世界を5つ足した）

### なぜこの5つか

v10 までの7つは、いま並べてみると**選び方が片寄っていた**。
ビートルズ／藤井風／モードジャズ／久石譲／シティポップ／ハウス／ローファイ ——
どれも「聴き心地のよい方向」で、**熱い・濃い・体温の高い音楽が1つも無い**。
0-2章で「ロックは押しの札が担っているから世界にしなくていい」と書いたが、
これは間違いだった。**押しの札はどの世界でも脇役**で、
「世界そのものが歪んでいる」状態にはならない。

そこで v11 では、空いていた「体温の高い側」を5つで埋めた。

| 足した世界 | キー | 何を埋めるためか |
|---|---|---|
| **ファンク／ソウル** | `P` | リズムそのものが主役の音楽。ホーンが吠える |
| **ハードロック** | `I` | いちばん音がでかい世界。歪んだギターの壁 |
| **レゲエ** | `O` | **拍の頭が抜けている**。世界でいちばん揺れる |
| **フラメンコ** | `H` | 手拍子と♭IIの緊張。ラテンのいちばん濃いところ |
| **ビッグバンド** | `J` | 158BPMの跳ね。管が全部いる、いちばん華やかな世界 |

これで世界の幅は次のようになった。

- **速さ**：74（レゲエ）〜 158（ビッグバンド）。v10 は 76〜132 だった
- **音量感**：ローファイ（`energyScale` 0.90）〜 ハードロック（1.14）
- **拍の置き方**：四つ打ち／8ビート／ワン・ドロップ（頭が無い）／
  3-3-2 の手拍子／4ビートの跳ね／ブーム・バップ／打点だけ

### レゲエのためだけに入れた例外：和音を裏拍へ送る

**世界は譜面に触らない**というのが v9 からの設計の柱だったが、
レゲエだけはそれでは成立しない。
レゲエの正体はテンポでも楽器でもなく、**和音が拍の頭に無いこと**だからだ。
ギターとオルガンが裏拍だけを弾く（スカンク）。
ここを守らないと、どれだけ音色を寄せても「ただの遅いポップス」にしかならない。

そこで最小限の例外を1つだけ作った（`music.js` の 8-a章）。
世界が `offbeat: ['chord']` と書いていれば、その役割の音符のうち
**拍の頭にあるものだけ**を8分ぶん後ろへ送る。

- もともと裏に置いてある音符（彩りのコンピングなど）は**動かさない**。
  一律にずらすと、裏にあった音が表に戻ってしまう
- 送り先がふさがっているときと小節からはみ出すときは、その音符を**落とす**。
  残すと拍の頭に音が居座り、そこだけレゲエでなくなる

実測（Node で全展開）：5つの性格すべてで、送ったあとに
**拍の頭に残った和音は 0個・空になった小節も 0個**。

### 直した不具合：世界の切り替えが途中で止まることがある

**症状**：フラメンコを含む切り替えを何度か往復すると、
`Start time must be strictly greater than previous start time` が大量に出て、
**世界の切り替えが最後まで終わらなくなる**（`worldBusy` が立ったまま）。

**原因**：フラメンコに入れた `drumMap: { s: 'c' }`（スネア→手拍子）が引き金。
「押し」の札はもともと**バックビートにスネアとクラップを両方**持っているので、
読み替えの結果**同じ瞬間に手拍子が2発**入る。
クラップは単音の `NoiseSynth` なので、同じ時刻に2回叩くと Tone.js が例外を投げる。

厄介なのは例外そのものではなく**巻き添え**のほうで、
叩いているのは `Tone.Sequence` のコールバックの中だから、
落ちるとその拍に予約してあった**他の処理まで一緒に止まる**。
世界の切り替えの後始末がそれに当たっていた。

**直し方**（`engine.js`）：

1. `monoSafe()` を追加。単音の合成打楽器は「時刻が進んでいなければ鳴らさない」。
   20ms のうちに2回叩ける奏者はいないので、音楽的に失うものは無い。
   クラップ・キック・スネア・ハイハット・タムに掛けた
   （タムは t1/t2/t3 で1つの音源を共有しているので、関も共有する）
2. 打点の呼び出しを `try` で包み、**1音の失敗が同じ拍の他の予約を巻き添えにしない**
   ようにした（`Part.tick` と `BaseBeat.hit`）

**確認**：20枚を重ねたまま世界を20回切り替えて、**例外0件・切り替えの失敗0件**。

## 0. v9 → v10 で変えたこと

### 0-1. なぜジャンルを足したのか（マーケティングの見立て）

v9 の4つの世界（ビートルズ／藤井風／マイルス＆エヴァンス／久石譲）は、
**選び方の軸が「作家」で揃っている**。音楽的には筋が通っているが、
想定している人 —— **音楽は好きだが、作ったことはない人** —— から見ると、
次の2つが弱かった。

**弱点1：4つとも「座って聴く音楽」だった。**
通りすがりの人が足を止めるのは、和音の複雑さではない。
**キックの位置と、裏で鳴るハイハットとクラップ**である。
v9 でいちばん体が動くのはビートルズの118BPMだが、それでも「8ビートのバンド」であって、
「その場で体が揺れる」種類の音ではなかった。

**弱点2：知っている名前がないと入口に立てない。**
「マイルス・デイヴィス」「久石譲」は、知っている人には強い言葉だが、
知らない人には**何も約束していない言葉**になる。
一方「踊れる」「夏の夕方」「勉強のとなり」は、音楽を作ったことがない人でも
**鳴る前から音が想像できる**。

そこで v10 では、**作家名ではなく「その場の体感」で選べる世界**を3つ足した。

| 足した世界 | 何を埋めるためか | 効く相手 |
|---|---|---|
| **ダンス（四つ打ち）** | 「体が勝手に動く」を最短で成立させる | 通りすがり全員。説明が要らない |
| **シティポップ** | 足を止めさせる16分の刻み＋豊かな和音 | 「音楽好き」を自認している層 |
| **ローファイ** | **1枚しか出していなくても様になる**受け皿 | はじめて触る人・自信がない人 |

**この3つを選んだ理由（このアプリの仕組みとの噛み合わせ）**

1. **四つ打ちは、重ねる順番が存在しない。**
   このアプリは「札を好きな順に足す」遊びなので、
   *どの順で足しても破綻しない音楽*ほど相性がいい。
   四つ打ちは全パートがループなので、そもそも順番の概念がない。
   ——「重ねていて気持ちいい」を、いちばん壊れにくい形で成立させられる。
2. **シティポップは、和音が豊かなのに濁らない。**
   maj9 / 7th / 9th が土台なので、20枚全部を重ねても和音がぶつからない。
   しかも16分のカッティングとクラップがあるので、遠くから聞いても「動いて」聞こえる。
3. **ローファイは、失敗が起きない。**
   テンポが遅く音数が少ないので、**1枚目からもう曲に聞こえる**。
   踊れる世界だけを足すと体験が「うるさい方向」にしか伸びないので、
   静かな側の受け皿として要る。久石譲（映画音楽）は静かだが、
   「壮大さ」を出すには複数枚を重ねる必要があり、最初の1枚には向かない。

### 0-2. 検討して、今回は入れなかったもの

正直に書いておく。以下は**良い案だが、v10 では見送った**。

| 候補 | 見送った理由 |
|---|---|
| **J-POP／アニソン風（速い長調）** | 効果は大きいと考えている。ただし「歌もの」の顔をしているのに歌が無いと、いちばん物足りなさが出る枠。ここは打ち込みの派手さより*旋律*の作り込みが要るので、譜面（PHRASES）に手を入れる回で扱いたい |
| **ボサノヴァ／ラテン** | 体は動くが、**モードジャズ（マイルス）と楽器も和音も近く**、並べたときの差が小さい。優先度を下げた |
| **ヒップホップ（重いトラップ系）** | 808のサブベースと3連ハイハットが要るが、いまの音源（実録音のドラムキット）では出せない。ローファイのほうが手持ちの音で成立する |
| **ケルト／民族音楽** | 目新しいが「体が動く」でも「知っている」でもないので、今回の狙いから外れる |
| **ロック（歪んだギター）** | すでに「押し PUSH」の札がどの世界でも担っているので、世界として立てる必要が薄い |

### 0-3. 土台のビートを、世界の持ちものにした

**v9 の穴**：札を1枚も出していないときに鳴っている土台のビートは、
**どの世界でも同じ8ビート**だった。
しかしこのアプリがいちばん長く鳴らしているのは「まだ誰も触っていない状態」であり、
**通りすがりの人が最初に耳にするのもそこ**である。

v10 では土台のビートも世界が持つ（`music.js` の `GROOVES`）。

| 世界 | 土台のビート | 中身 |
|---|---|---|
| 標準／ビートルズ | `eight` | 素直な8ビート（v9 と同じ） |
| 藤井風／シティポップ | `boogie` | 16分ハット＋3拍目裏のキック |
| ダンス | `four` | **四つ打ち**＋裏ハイハット＋クラップ |
| ローファイ | `boom` | もたつくブーム・バップ（キックを拍から外して置く） |
| マイルス | `ride` | ライド中心。キックは触るだけ（フェザリング） |
| 久石譲 | `cinema` | 拍を刻まず、ティンパニで場面を押すだけ |

つまり **ダンスの札を出せば、札が0枚でも四つ打ちが鳴っている。**
`fill`（飾り）は重なっている札の枚数で増えるので、
0枚のときはスカスカ、増えるほど賑やかになる。

### 0-4. 直した不具合：裏のタブに回すと札を受け付けなくなる

**症状**：スタイルカードを出したあとブラウザを裏に回して戻すと、
それ以降どの札も入らなくなる（v9 にも同じ穴があった）。

**原因**：世界の切り替えの後始末（`worldBusy` の解除）を
`Tone.Draw`（＝画面の描画に合わせて呼ばれる仕組み）だけに任せていた。
タブが裏に回ると描画が止まるので、**後始末が一度も呼ばれない**。

**直し方**：実時間のタイマーでも同じ後始末をするようにした（`app.js` の `settle()`）。
Chrome で実際に裏タブのまま切り替え → 札の投入まで通ることを確認した。

## 1. v3 から何を変えたのか

### 問題：ジャンルと世界が二重になっていた

v3 の列は **ロック／ジャズ／クラシック／エレクトロ／ポップ** というジャンルだった。
そこにスタイルカード（世界）を足した結果、

> **「マイルスの世界の、ロックのカード」**

という意味の通らない札ができてしまった。
しかも楽器は「エレキギター → ハープ」のような**機械的な読み替え**で決めていたので、
その音楽に実在しない編成（ジャズの世界にシンセパッド等）が平気で出ていた。

### v9 の答え：札は「はたらき」だけ持つ。楽器は世界が持つ

| | v3 | v9 |
|---|---|---|
| 列 | ジャンル（ロック／ジャズ…） | **性格**（軸／歌／押し／刻み／彩り） |
| 札が持つもの | 譜面 **＋ 楽器** | **譜面だけ** |
| 楽器を決めるのは | 札（＋機械的な読み替え） | **世界（20枠を手で決めた編成表）** |
| その音楽に無い楽器 | 混ざりうる | **最初から存在しない** |

**実測：13の世界すべてで同じ編成のままの札は 0 / 20 枚**（v11 時点。v9 では5世界で 0/20）。
どの札も、世界が変われば必ず別の楽器で鳴る。

## 2. カードの列＝性格（CHARACTER）

ジャンルではないので、どの世界にも5つとも存在する。

| | 意味 | 譜面の中身 |
|---|---|---|
| **軸 CORE** | 背骨 | 素直な8分。口ずさめる形 |
| **歌 SING** | 伸びる | 長い音。4小節でひとつの物語 |
| **押し PUSH** | 前へ | 8分で押し出す。いちばん力強い |
| **刻み DRIVE** | 走る | 16分の反復。機械的な推進力 |
| **彩り COLOR** | 飾る | 裏拍と合いの手。休符が主役 |

各マスに出るのは **はたらき**（世界が変わっても変わらない）と、
その下に小さく **いまの世界での楽器**（世界が変わると入れ替わる）。

## 4. 編成の根拠（調べたこと）

### ビートルズ

『ラバー・ソウル』で**ハルモニウム**を導入し、『リボルバー』では
「エリナー・リグビー」の**弦楽八重奏**とホーンの編曲を持ち込んだ。
「Think for Yourself」では通常のベースに**ファズベース**を重ねている。
ポール・マッカートニーのベースは12度を駆け上がるなど旋律的。

→ 「歌」の列を弦とハルモニウムに、「押し」のベースにファズベース層を、
「彩り」をホーンセクションに割り当てた。

出典：[Guitar World「Rubber Soul の楽器」](https://www.guitarworld.com/magazine/guide-songs-and-instruments-featured-beatles-rubber-soul-album)、
[Wikipedia: Rubber Soul](https://en.wikipedia.org/wiki/Rubber_Soul)、
[Wikipedia: Revolver](https://en.wikipedia.org/wiki/Revolver_(Beatles_album))

### 藤井風

全曲を **Yaffle** が編曲・プロデュースしており、
「ドラムやベース、ギターやサンプリング音源でのプログラミング、ストリングス、
ホーンセクションなどを合わせて組み立てていく」手法。
つまり**生楽器と打ち込みが同居する**。中心はあくまでピアノ。

→ v3 では全部ピアノに寄せていたが、v9 では
「刻み」だけを打ち込み（シンセベース＋LINN）に、「歌」をストリングスに、
「彩り」をホーンとゴスペルのオルガンに分けた。

出典：[Yaffle の制作手法](https://note.com/ancora/n/n844dd6bb6d4c)、
[藤井風 - Wikipedia](https://ja.wikipedia.org/wiki/%E8%97%A4%E4%BA%95%E9%A2%A8)

### マイルス・デイヴィス／ビル・エヴァンス

『カインド・オブ・ブルー』の六重奏は
**トランペット／アルトサックス／テナーサックス／ピアノ／ウッドベース／ドラム**。
**ギターもシンセも1本も入っていない。**

→ この世界には**ギターとシンセを1つも置かなかった**（テストで検査している）。
ベースは全枠ウッドベース。和音はすべてピアノ。

出典：[Kind of Blue（編成）](https://en.wikipedia.org/wiki/Kind_of_Blue)、
[アルバム解説](https://bestofjazz.org/miles-davis-kind-of-blue/)

### 久石譲

大編成ではなく**小さめのオーケストラ**を使い、楽器と音色を場面ごとに丁寧に描き分ける。
『風の谷のナウシカ』などでは**ミニマル・ミュージックの手法**
（動きを最小限にした反復）が使われている。

→ 弦・ピアノ・ハープ・木管・ホルンだけで組み、
**「刻み」の札をミニマルな反復**（シロフォン＝グロッケン役）に当てた。
金管が前に出るのは「押し」だけ。

出典：[久石譲 - Wikipedia](https://ja.wikipedia.org/wiki/%E4%B9%85%E7%9F%B3%E8%AD%B2)、
[久石譲っぽいコード進行の作り方](https://musekinote.com/gibli_code/)、
[『あの夏へ』の解説](https://type00k.com/one-summer-day-day/)

> ⚠️ ここに書いたのは**「その音楽の特徴として一般に解説されている事柄」**であって、
> 本人の制作手順ではない。似せているのは編成・和声・テンポ・ノリであって、
> 旋律そのものではない。**「〜風」であって「〜の曲」ではない。**

### シティポップ（v10）

1970〜80年代の日本のシティポップは、スタジオ・ミュージシャンの生演奏を土台に、
**エレキギターのカッティング／エレキベース／ドラム／エレクトリック・ピアノ**、
そこに**ストリングスとホーンセクション**を重ねる形が定型だった。
シンセは効果として使われ、主役にはならない。

→ 「刻み」の札を**16分のカッティング**に当て、「押し」と「彩り」をホーンに、
「歌」をストリングスにした。エレクトリック・ピアノの音源が無いので、
その役はピアノとオルガンが代わりに担っている。
ドラムだけ「刻み」で LINN（80年代のドラムマシン）に切り替わる。

### ダンス／四つ打ち（v10）

ハウスは1980年代のシカゴで、**ドラムマシンとシンセベース**の上に、
**ピアノのコード（ピアノ・ハウス）**やストリングス、サックスを重ねる形で成立した音楽。
生ドラムではなく**ドラムマシンの音**であることが要点。

→ キットは Techno と CR78（v9 まで一度も使っていなかった2つ）を当てた。
低音はシンセベース＋サブベース固定。上物はピアノ・オルガン・弦・サックスで、
**「打ち込みの上に生楽器を1つ置く」**というハウスの作り方をそのまま編成にしている。

### ローファイ・ヒップホップ（v10）

ジャズのレコードから切り出した音を、**テープや古い機材を通した「こもった音」**で
鳴らすのが特徴。テンポは80前後、16分が跳ねる。

→ この世界だけ**全パートに高域カット**（`lp`）を入れてある。
2000〜3000Hz から上を削ると、同じピアノでも「レコードから鳴っている」音に変わる。
部屋の響きも `air: -4.0`（高域を下げる）・`mud: +1.0`（中低域をわざと残す）にしてある。

### ファンク／ソウル（v11）

ジェームス・ブラウンが楽団に徹底させたのが「ザ・ワン」＝**1拍目を全員でそろえること**で、
そのかわり和音はほとんど動かさない。ここでも進行は I7 を2小節続けてから
IV9 → V7(♯9) と動くだけにしてある。**動かないからこそリズムが立つ。**

土台のビート（`funky`）にはゴーストスネア（聞こえるか聞こえないかの弱い打点）を
7と14に置いた。ここを消すと途端に打ち込みくさくなる。

編成はホーンセクション（サックス＋トランペット＋トロンボーン）、
16分で刻むギターのカッティング、オルガン、エレキベース。
残響は全世界でいちばん少ない（`sendScale` 0.50）。60〜70年代のスタジオは乾いていた。

### ハードロック（v11）

音の芯は「歪んだギターを左右に2本置くこと」なので、`panScale` を 1.15 まで上げて
左右いっぱいに広げてある。和声は Em – Cadd9 – G – D（i–♭VI–♭III–♭VII）。
ロックのアンセムはほぼこの4つで書かれている。

ベースは**低いミ（E1）から始める**。エレキベースの最低音であり、
ロックがこの音を土台に選んだのは単にそこが一番低いからだった。

**ギターだけの世界にはしていない。** ハードロックは同時に
オルガン（ディープ・パープル）・弦（レッド・ツェッペリン）・ピアノ（クイーン）を
持ち込んだ音楽でもあるので、「歌」「彩り」の枠はそちらへ寄せてある。

### レゲエ（v11）

土台のビートはワン・ドロップ（`onedrop`）。
**1拍目にキックを置かず、3拍目でキックとスネアが同時に落ちる。**
頭が抜けているぶん、聴く側が勝手に体で拍を埋めにいく。
レゲエの「重さ」の正体はテンポではなくこの空白のほうにある。

和音は 0-0章の `offbeat` で裏拍だけに送っている（スカンク）。
ベースが最前面に出て（−1dB、全世界で最も大きい）、旋律よりも太く低く歌う。

旋律にハルモニウムを当てているのは**メロディカの代役**で、
どちらもリードを空気で鳴らす楽器。オーガスタス・パブロがこの音でダブの旋律を作った。
`delayScale` を 1.60 まで上げてあるのはダブの名残。

### フラメンコ（v11）

和声は Am – G – F – E、アンダルシア終止。4小節ぜんぶ下がっていって、最後の E で止まる。
この E に♭9（ファ）を入れてあるのが「スペインの音」の正体で、
旋律の梯子も E のところだけ **E F G# A B C D（フリギア・ドミナント）** に切り替わる。
**同じ札が4小節目だけ違う色になる**のはこのため。

打楽器はスネアを `drumMap` で**手拍子（パルマス）に置き換えて**ある。
フラメンコに太鼓は無く、拍を刻むのは人の手とカホンだから。
土台のビートも 3-3-2 で数える（スペインの数え方）。
※ この読み替えが 0-0章の不具合を引き起こしたので、対処もそこに書いてある。

ガットギターだけの世界にはしていない。「歌」は弦楽、「押し」はスペインの金管、
「彩り」はフルートとハープに振ってある。

### ビッグバンド／スウィング（v11）

この世界だけ**管楽器が全部いる**（トランペット・トロンボーン・サックス・クラリネット）。
ビッグバンドは「管のセクションを塊で鳴らす」音楽なので、
和音の役割にもトロンボーンとサックスを当ててある。

ピアノは**ルートを弾かない**（`rootless`）。
ルートはウッドベースが4分で歩いて受け持つ、という分業がこの音楽の設計だから。
アコギはフレディ・グリーン式の刻み。

テンポ158・跳ね0.55 で全世界最速。
ただしトロンボーンやウッドベースは 8-b章の `minGap` で16分が間引かれるので、
速くしても濁らない。**吹けない速さは自動で吹かない。**

## 5. 和声とテンポ（v3 から引き継ぎ）

| 世界 | 進行 | テンポ | ノリ | ハモリ |
|---|---|---|---|---|
| 標準 | Cm9 → A♭maj9 → E♭6/9 → B♭sus9 | 開始画面で選んだ値 | — | — |
| ビートルズ | D6/9 → **E7(長調のII)** → G6/9 → **C6/9(♭VII)** | 118 | — | **3度上** |
| 藤井風 | Fm9 → B♭9 → E♭maj9 → **C7♭9** | 88 | 16分の跳ね | — |
| マイルス | Dm11 → Dm11 → **E♭m11** → Dm11 | 132 | 8分の跳ね | — |
| 久石譲 | Cadd9 → Fmaj9 → **E♭maj9(♭III)** → **Fm9(借用Ⅳm)** | 76 | — | — |
| **シティポップ** | Fmaj9 → **E7(9)** → Am9 → G9 | **114** | 16分の跳ね（浅く） | **3度上** |
| **ダンス** | Am9 → Fmaj9 → Dm9 → Gsus9 | **124** | — | — |
| **ローファイ** | Dm9 → G13 → Cmaj9 → **A7(♭9)** | **82** | 16分の跳ね（深く） | — |

v10 で足した3つの進行の考え方：

- **シティポップ**：ハ長調のまま3小節目へ行く前に **E7（本来ハ長調に無い和音）**を挟む。
  この1つだけで「ただの明るい曲」が「夕方の曲」になる。シティポップの常套句
- **ダンス**：イ短調の i–VI–iv–Vsus。**4つとも重い和音を避けてある**ので、
  20枚重ねてもキックとベースの居場所が残る
- **ローファイ**：IIm–V–I の後に **VI7(♭9)** で振り出しへ戻すジャズの定型。
  どの札を足しても外れた音にならない＝はじめての1枚が失敗しない

各進行を選んだ根拠は v3 の README「8. スタイルカードの設計根拠」に詳しく書いてある
（v9 でも進行そのものは変えていない）。

演奏キー（`QWERT` `ASDFG` `ZXCVB`）とも、ミキサーの `M` ともぶつからない位置を選んである。

`M` **ミキサー**（札ごとの音量。9-b章）の開閉。
`M` を選んだのは、カードUIDの16進（`0-9` `a-f`）にも
演奏キーにも入っていない文字だから。リーダーの読み取りと衝突しない。

### 同じ札をもう一度＝その音を外す

**鳴っている札をもう一度タッチ（同じキーをもう一度）すると、その音が外れる。**
カードを2枚用意しなくても、1枚で足し引きができる。

- 入れたとき … G5（784Hz）の「ポーン」
- 外したとき … **1オクターブ下の G4（392Hz）を短く**。取り違えないように音を分けてある
- 着弾待ち（合図は鳴ったがまだ音が入っていない状態）の札も、もう一度タッチで取り消せる
- **同じ札の連続入力は 900ms 無視する。** リーダーは札をかざしたままだと同じUIDを
  何度も送ってくるので、これが無いと「入る→外れる→入る」とばたつく

### 同時枚数に「無制限」を追加

開始画面の「同時に鳴らせる枚数」に **無制限** を足した。
選ぶと古い札が押し出されなくなり、**20枚すべてを重ねられる**。

- 重ねる札は20枚しかないので、無制限でも実際の上限は20枚
- 枚数連動のゲインには**上限（2.05倍＝10枚のときの値）**を付けてある。
  外すと最終段で潰れて「足しても大きくならない」（v2 の失敗）に逆戻りするため
- 画面のメーターは無制限のとき20個の枠になる（細く表示する）

## 6-b. カードリーダーについて

リーダーはキーボードとして動作し、カードをかざすとUIDを1文字ずつ打ち込んで Enter を送る。
登録は `register.html` で行う（32枚ぶん）。

### UIDは16進数（英字を含む）

このリーダーが送ってくるUIDは **`010095e40c5553` のような16進数**で、
**a〜f の英字が混ざる**。ここが原因で一度壊れていた。

> **直したバグ：** 入力処理が「数字だけ」をUIDとして拾っていたため、
> ① UIDから英字が抜け落ちて `CARD_MAP` に一致せず、正しい札が鳴らない
> ② しかも `a` `b` `c` `d` `e` `f` はすべて演奏キーなので、カードをかざすたびに
>    **関係のない札が次々に鳴る**
> という二重の事故になっていた。
> （実測：登録済み20枚のうち19枚が誤動作。例 `010095e40c5553` は
> 「軸のメロディ」が鳴るはずが「押しのベース＋押しのコード」が鳴っていた）

いまは **英数字をすべて同じ道に通している。** 1文字来たら

1. UIDバッファに足す（400ms 何も来なければ捨てる）
2. その文字が演奏キーなら、すぐには鳴らさず **45ms だけ待つ**

リーダーの入力なら次の文字か Enter が45ms以内に来て打ち消される。
手押しなら45ms後にふつうに鳴る（人には分からない遅さ）。

未登録のカードをかざすと **「未登録のカードです（UID: …）」** と表示される。
その UID を `register.html` で割り当てればよい。

### かざしたときの「ピッ」を消したい場合

**結論：アプリ側からは消せない。付属の設定カードでも消せない。**
残る手は「ブザーを物理的に黙らせる」ことだけ。

#### なぜアプリから消せないのか

この音はリーダー本体に載っている**圧電ブザーが自分で鳴らしている**。
リーダーは USB キーボードとして振る舞い、ブラウザに届くのは
「キーが押された」という情報だけで、ブザーが鳴ったことは通知すらされない。
**JavaScript から止める手段が構造的に無い。**

#### 設定カードでも消せない（実物の解説書で確認した）

付属の `Mifare Reader Configuration Card` に書かれている設定項目は、
**出力フォーマットとキーボード配列だけ**で、**ブザーの項目は無い**。

| 設定値 | 内容 |
|---|---|
| 1〜28 | output formats of reader（出力の書式） |
| **29 E** | QWERTY キーボード配列（**既定値。このアプリはこれが前提**） |
| 30 F | AZERTY キーボード配列 |
| 31 PS2 | フォーカスされた窓へ送信 |
| 32 USB | Mifare ライター用。**ソフトから命令を送るまでカードを読まなくなる** |

書き起こしと写真は `reference/カードリーダー解説書/` にある。

> ⚠️ **1〜28 を総当たりで試すのは勧めない。**
> これらは「出力の書式」なので、変えると UID の打ち込まれ方が変わり、
> アプリがカードを認識できなくなる。ブザーに効くという記述もどこにも無い。
> **32（USB）にすると、アプリからは完全に読めなくなる。**
> （もし変えてしまったら、解説書の裏面にある抜き差しを繰り返す手順で戻せる）

#### 実際に消す方法：ブザーを物理的に塞ぐ／外す

これが確実な唯一の手段。

1. **穴を塞ぐ（元に戻せる・いちばん手軽）**
   本体のブザーの小さな穴に、粘着ゴム（ひっつき虫等）やテープを詰める。
   音量はかなり下がるが、完全な無音にはならないことが多い。
2. **ブザーを外す（元に戻せない・確実）**
   ケースを開け、基板上の丸い部品（圧電ブザー）の配線を切るか外す。
   完全に無音になる。**ケースを開けるので保証は効かなくなる**。

> 私は実機を触れないので、**どちらも実際に試した結果ではない**。
> 2 は分解を伴うので、ためらう場合は 1 から試すのが安全。

#### 付属ソフト（EasyMF）について

解説書には `http://www.FissaiD.cn/EasyMF` というライター用ソフトの
入手先が書かれている。ただし **これは勧めない。**

- 出どころを検証できない海外サイトの実行ファイルであること
- そもそもこれは **32（USB ライターモード）用**のソフトで、
  そのモードにするとアプリからカードが読めなくなること

## 8-b. 楽器ごとの「鳴りきる長さ」（v9.1 で追加）

**問題**：ウッドベースやトロンボーンが、短い音符ではまったく聞こえなかった。

**原因**：譜面（`PHRASES`）の音の長さ（`16n` など）は楽器を知らない。
それを `engine.js` がそのまま `triggerAttackRelease` に渡していたため、
どの楽器も同じ長さで切られていた。

`samples/` の実録音を全部デコードして、5msごとのRMSが
最大音量に達するまでの時間を測ったところ、楽器差は次のとおりだった。

| 楽器 | 音量50%到達（中央値） | 80%到達（中央値） |
|---|---|---|
| ピアノ | 0.015秒 | 0.020秒 |
| シロフォン | 0.030 | 0.035 |
| エレキギター | 0.025 | 0.030 |
| エレキベース | 0.030 | 0.045 |
| ハープ | 0.065 | 0.070 |
| サックス | 0.050 | 0.065 |
| トランペット | 0.055 | 0.085 |
| ホルン | 0.115 | 0.180 |
| クラリネット | 0.160 | 0.240 |
| トロンボーン | 0.165 | 0.495 |
| オルガン | 0.170 | 0.635 |
| ハルモニウム | 0.190 | 0.605 |
| バイオリン | 0.120 | 1.425 |
| チェロ | 0.230 | 0.525 |
| **ウッドベース** | **0.250** | **0.885** |

**ピアノは0.02秒で鳴りきり、ウッドベースは0.885秒かかる（44倍）。**
16分音符は132BPMで0.114秒しかないので、ウッドベースは
音量の25%も出ないうちに切られていた。これが不具合の実体。

**直し方**：`music.js` の `VOICES` に楽器ごとの2つの値を持たせた。

- `speak` … その楽器が音になるまでに要る秒数（上の実測の80%到達を、上限0.45秒で使う）。
  譜面の音符がこれより短ければ `engine.js` が**ここまで伸ばす**。
- `minGap` … その楽器が実際に出せる音と音の最短の間隔（秒）。
  これより詰まった音符は**間引く**。太い管や弓の楽器に16分の連打を
  書いても実際には吹けないので、間引いて8分相当にしたほうが
  その楽器らしく鳴り、低音も濁らない。

サックス・クラリネット・フルート・バイオリンは実測でも速く、
実際に細かく吹ける楽器なので `minGap` は 0（間引かない）。
`minGap` を入れたのはハルモニウム(0.16)／ホルン(0.14)／チェロ(0.16)／
トロンボーン(0.20)／ウッドベース(0.20)／シンセパッド(0.25) の6つだけ。

処理は `engine.js` の `Part.soundLength()` にある。
判定は**音ごとではなくイベントごと**に1回だけ行う
（音ごとにやると和音の2音目以降が消えてしまうため）。

## 9. 音を調整したいとき

**`music.js` の `WORLDS` だけ触れば、その世界の音がすべて変わる。**

- `voices[性格][役割]` … その札をその世界で何で鳴らすか（★これが v9 の主役）
- `prog` / `bpm` / `swing` / `harmony` … 和声とノリ
- `sendScale` / `air` / `mud` / `panScale` … 部屋の響き
- `drumMap` … 打楽器の読み替え（`h: null` でハイハットを消す 等）
- `groove` … **土台のビート**（`GROOVES` の名前。v10 で追加）
- `offbeat` … その役割の和音を裏拍へ送る（`['chord']`。v11 で追加。いまはレゲエだけ）
- `move` … スタイルカードに出る「ノリ ●●●」の数（1〜3）。音には影響しない

譜面を変えたいときは `PHRASES`。こちらは**全世界に影響する**。

## 9-b. ミキサー：札ごとの音量を、聴きながら決める

**なぜ作ったか。**
上の `WORLDS` には、札1枚ぶんの楽器の `gain` が世界ごとに手で書いてある。
だが「実際に重ねて聴いたときの釣り合い」は、
数字を書き換える → 保存する → ブラウザを読み直す → もう一度その世界にして
同じ札を並べ直す、を繰り返しても決まらない。
**耳で合わせるには、鳴っている音をその場で動かせる必要がある。**

### 使いかた

1. ふつうに `はじめる.bat` で始める
2. <kbd>M</kbd>（または右上の「ミキサー」）でパネルを開く
3. **札の名前を押すと、その札が鳴る／止まる**（もう一度で止まる）
4. **スライダーを動かすと、その場で音量が変わる**（0.08秒かけて滑らせるので段差が出ない）
5. **S** …その札だけ聴く（ソロ）／**M** …その札だけ消す（ミュート）
6. 決まったら **「保存する」** → `card-gain.js` に書き込まれる

- パネル内でキーを打っても札は飛び出さない（演奏キーの横取りを止めてある）
- 「同時枚数の上限を外す」を入れると、調整のあいだだけ20枚全部を重ねられる
- 一番上の行は **土台のビート**（札が0枚のときも鳴っているドラム）

### 2段構え：共通 と この世界だけ

楽器は世界ごとに違うので、ちょうどよい音量も世界ごとに違う。
そこで値を2つ持たせてある。

| | 効く範囲 | 使いどころ |
|---|---|---|
| **共通** | 全部の世界 | 「メロディ全体がいつも大きい」など、世界に関係のないずれ |
| **この世界だけ** | いまの世界 | 「久石譲のホルンだけ埋もれる」など、その編成に固有のずれ |

**実際に効く値 ＝ 共通 ＋ この世界だけ**。
ふだん触るのは「この世界だけ」のほうでよい。

### 値の行き先

- スライダーを動かした時点で **localStorage** に入る（読み直しても残る作業中の控え）
- 「保存する」で **`card-gain.js`** に書き出す。こちらが本番の値で、
  localStorage を消しても効く（そのとき控えは自動で捨てる）
- 書き込みは `server.js` に足した `POST /save-card-gain` が受ける。
  **書き換えるのは `card-gain.js` の1ファイルだけ**で、内容も
  `window.CARD_GAIN =` で始まるかを確認してから書く
- Python の `http.server` で開いているときはこの口が無いので、
  自動でファイルのダウンロードに切り替わる（手で置き換える）
- `.js` `.css` `.html` は `Cache-Control: no-store` で返すようにした。
  保存したのに古い値が読まれる、を防ぐため

### 音への効かせかた（実装）

`Part` の出口の `gain` に、この dB を足しているだけ。

- 新しく作る `Part` は、生まれた時点の値を読む（`Mixer.effective(id)`）
- 鳴っている `Part` は `setOffset()` で動かす。
  登場の膨らみ（2小節かけて定位置へ）の途中で動かされることがあるので、
  予約済みの変化を取り消し、**現在値を基準に**引き直している
- 土台のビートも同じ仕組み（id は `_beat`）
- ソロ／ミュートは −60dB を掛けるだけで、**保存はしない**（その場かぎりの試聴）

`card-gain.js` が空（全部 0）のときは、v10 のこれまでと**まったく同じ音量**になる。
